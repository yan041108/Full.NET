### 新边界归因

失败样本的发生器 401/403 合并计数为 399，错误率约 1.493%；服务端 HTTP 指标明确记录了 401。JWT 到期时间为 `2026-10-16T02:30:44+08:00`，样本记录结束为 `02:21:53.985+08:00`，排除该段凭据自然到期。

本轮新归档日志中，权威会话查询 `identity.find_refresh_session_by_explicit_session_id` 有 407 条 `ServiceCapacityExceededException`，都位于失败测段记录窗口内；服务端两个节点的 401 累计为 201 + 206 = 407。最后一次异步指标导出的两个节点准入 timeout 累计计数为 173 + 179 = 352。新失败系列在 before 中不存在，且异步导出未覆盖日志终态，不能补零或声称有完整 399 次指标增量。日志/服务端 407、发生器响应 399 和准入导出 352 的统计边界不同，不能强行逐项等同，也不将中止时在途响应算成已被发生器记录的响应。

沿当前与冻结代码共同的调用链，普通会话读取遇到容量异常时不满足独立授权作用域的重抛条件，落入 `AccessSessionValidator` 通用捕获并返回 false，随后 `FullNetJwtBearerEvents` 将其认证失败。因此，**池预算配置生效仍不足以消除依赖过载被表现为 401 的问题**；这次 SQL Server 失败也不能解释成 MySQL 服务端 1040。异步采样的准入占用/排队快照不足以给出瞬时饱和峰值，不据此推断持续队列满或某个 CPU/锁是唯一性能根因。

保持 fail-closed 是必要的；区分过载与无效凭据并不允许复用陈旧会话或放行请求。本批没有修改认证返回契约，也没有提高许可、延长超时或收窄档位后宣称原失败通过。
