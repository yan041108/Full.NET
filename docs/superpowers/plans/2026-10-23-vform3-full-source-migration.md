- 完整来源固定为 `vform666/variant-form3-vite@c67479e496bab56a93a3dff168a4f529d8293c67`，采用记录对应 3.0.10；迁入前核对该提交、完整文件清单、内容摘要、许可及作者声明，不用浮动 master。范围以该来源实际具备的完整功能为准。

- 首阶段只做完整迁入所需的工具链、依赖、别名、资源路径、生命周期和宿主集成；Full.NET 业务选择器、真实数据源、文件服务及工作流字段权限在原版对齐后再扩展。不能把原版已有的文件/图片、富文本等组件迁入推到后二开。

- 原版脚本、事件、样式及相关编辑器保留；设计器/预览的可执行能力采用独立隔离 Web 运行域。宿主保持原有认证与 CSP，隔离域不持有管理端凭据、宿主 DOM/存储或无约束业务 API。不能简单删除能力或全局放宽宿主 CSP 规避适配。

## 2. 实施前缺口与验收目标

2026-10-23 使用 `node --input-type=module` 直接调用当时的 `vform3-adapter.ts` 完成最小复现，形成下列缺口。该旧适配器现已删除，修复与实际往返证据见[验证记录](../../verification/2026-10-24-vform3-full-source-migration.md)；下表保留实施前事实与验收目标。

| 问题 | 当前结果 | 必须达到的行为 |
| --- | --- | --- |
| 显示名称 | “申请标题”往返后变为机器码 `title` | 标签与 FieldKey 分别保留 |
| 选项 | `label=采购申请 / value=purchase` 往返后标签变为 purchase | 保留标签、值、顺序和原版合法值类型 |
| 默认值与占位 | 转为 Schema 后丢失 | 保存读取与预览一致 |
| 表单外观 | labelWidth=180、top、large 回显为固定 120/left，尺寸丢失 | 原版表单配置完整保留 |
| 附件与子表 | 转换为 input，往返后专用约束为空 | 不降级，保留完整组件、嵌套结构和专用配置；业务发布未支持时明确诊断 |
| 栅格布局 | 保存转换返回 unsupported component | 原版容器可设计、保存、回显、预览及导出 |
| 交互和工具栏 | 卡片与上下按钮替代拖拽，未完整提供原版操作 | 原版交互及工具栏逐项运行并验收 |

仅验证宿主 `getFormJson/setFormJson` 自身相等不足以关闭问题，必须经过真实 API、数据库、重新进入设计页及导出后比较完整设计资产。

## 3. 连续实施顺序

按 VF-F1 → VF-F2 → VF-F3 → VF-F4 连续推进。内部检查项不是提交、全量测试或等待确认的门禁；不自动创建工作树、多代理或逐步提交。真实前置失败时停止依赖项，继续安全独立工作。VF-F1–F4 是原版完整对齐阶段，后续业务二开不以其名义提前裁剪范围。

### VF-F1：完整来源和隔离宿主（已实施，聚焦验证）

**涉及区域：** `packages/admin-form-designer/src`、`vendor/vform3`、包依赖/构建配置、管理端宿主及实际受影响的 Web 运行域配置。完整上游源码的具体子目录在复制前按来源清单固化。

- 读取上游 `widget-panel/widgetsConfig.js`、扩展注册、容器/字段组件、setting-panel、toolbar-panel 及渲染器，建立完整功能清单；每项记录上游文件、目标文件、适配差异、支持状态和验收场景，不能只计组件入口数量。
- 完整迁入源码与资源，在现有 Vue/Vite/Element Plus 工具链中挂载；替换 `vform3-loader.ts` 指向自研精简面板的实现，不恢复已知画布异常的旧 UMD 作为最终方案。保留通用宿主公共接口，必要契约调整同步所有调用方。
- 固化独立运行域的部署来源、sandbox 权限、域内 CSP 和强类型通信协议；完整设计 JSON 不通过 URL/日志泄漏。通信校验来源、窗口、消息类型、关联请求和大小，不转发 Token/Cookie。传入配置字符串不可由 API/Worker 执行。
- 隔离覆盖设计、预览及正式 Web 填报，不能在上线填报时把可执行设计内容重新挂到管理端同源 DOM。凭据由可信宿主持有；消息只允许固定的数据读写/校验操作，不能接受任意 URL、方法或 Header 让宿主代发请求。隔离域的请求、图片/媒体、表单提交、导航和弹窗等出站通道按用途限制；预览只用测试数据，正式业务数据只送到授权绑定。部署检查 Cookie 作用域、API 凭据来源校验及隔离域策略，不把“不同域名”单独当作隔离证明。
- 在隔离域验证原版脚本/事件/CSS、预览、源码/SFC 编辑及所需依赖可用；外部行为使用受控测试端点验证。不能靠隐藏按钮、删除编辑器或吞异常宣布兼容。
- 保留原版语言、样式和全部属性入口；解决样式冲突通过运行域/宿主边界，不删原版布局。包体重新测量并建立完整版本基线，不能沿用精简子集 8 KB 预算，也不能无实测抬高预算。

**聚焦验证：** 源码/资源清单与功能清单完整，首次/重复挂载、第二次覆盖载入、卸载和多宿主隔离；原版可执行预览与宿主凭据/DOM 隔离，以及伪造消息、越界出站和宿主代发请求被拒绝。正式填报复用该边界，在 VF-F4 以真实授权数据验证。先通过宿主与源代码适配的必要检查，再开展依赖此宿主的页面验证。

### VF-F2：无损设计资产与版本持久化（已实施，双库及真实页面链路已验）

**涉及区域：** `WorkflowFormManagementService`、ManageForms DTO/Endpoint、`WorkflowSql`/记录、双库 Workflow 表单迁移、`packages/client-contracts`、`ui/admin/src/api/workflow-forms.ts`、`WorkflowFormsView.vue`、`VForm3WorkflowDesigner.vue` 与 `vform3-adapter.ts`。

- 将草稿保存从“VForm JSON → 简化 Schema → 持久化”改为完整设计资产 DTO；包含 DesignerJson、来源提交/格式版本、内容摘要及 ExpectedDraftRevision。业务校验投影在发布时生成，不作为回显数据源。
- 原始设计 JSON 完整保留布局树、组件 ID/顺序、属性、事件/样式、未知但属于支持来源格式的扩展字段；不扁平化、不改标签、不把组件降为 input。输入只接受有界纯 JSON，未知格式/不合法结构明确拒绝，不因业务编译器暂不消费某项而删除它。
- 读取 API 返回已保存设计资产；保存响应与重新进入页面都加载同一内容。设计草稿修订与运行表单修订分离，二人并发保存必须冲突，不覆盖对方更新；WF-R1 所需 ExpectedFormRevision 与本批统一维护，不重复造并发协议。
- SQL Server/MySQL 成对实现目标结构、索引与迁移失败恢复。保留旧草稿/版本事实，按开发底座直接演进同步改调用方，不保留无实际消费者的双轨兼容路径。旧简化 Schema 已丢失的信息无法自动恢复；实际需要保留的旧设计只能明确标记为重建结果并校对，禁止臆造原标签或宣称无损恢复。
- 设计资产的 Tenant/Host 授权、大小/深度/节点上限、摘要和审计与现有机制衔接；普通待办用户不能凭实例读取设计权限接口。定义内容不应包含真实密钥，外部业务凭据使用引用。

**聚焦验证：** 对完整 JSON 执行创建/保存 → API/双库读取 → 重开设计页 → 编辑再保存 → 导出 → 导入；除对象键序/非语义空白外做结构等价比较，覆盖上表所有损失复现、嵌套容器、选项值类型、样式、事件和扩展配置。验证越权/跨租户、旧修订冲突、超过边界拒绝及对应部分迁移恢复。

### VF-F4：发布/运行边界与交付收口（已实施，定向链路验收通过）

**涉及区域：** 表单发布编译器/版本持久化、Web 渲染适配、服务端字段校验、绑定清单、页面操作权限及真实调用方。

**范围界线：** 本批接续现有 Workflow 保存、发布与办理链，落实原版渲染器接入所必需的授权投影和提交协议；它是完整替换旧设计器的必要集成。新增 Files/目录连接器、业务控件和规则编辑能力留到后二开，不作为本批完成前置。现有字段映射逐项核验；无法在本批正确运行的映射明确标为不支持并阻止相关业务发布，不能影响原版设计/保存/预览验收。

- Publish 从指定草稿修订生成不可变完整设计快照、Web 渲染快照、业务校验模型、绑定清单、来源/格式版本与各自 Hash，原子提交；不得继续给 FormSchemaJson/WebRenderSchemaJson 写入同一简化 JSON 作为完整 VForm 集成。
- 固化绑定清单的组件 ID、原版模型路径、FieldKey、业务类型及双向值编解码规则；遍历全部来源容器，区分布局表格与业务子表。同一组件类型不隐式决定业务类型：number 的整数/小数/金额，date 的单值/日期时间/范围，select 的单选/多选需分别校验。保留选项的字符串、数字、布尔类型差别及 null/空值语义；金额/精确小数不得先转为 JavaScript Number 再字符串化。不支持的值形态或精度明确拒绝该业务绑定，原设计 JSON 不改写。重复模型名、重复/悬空绑定及字段重命名必须有发布诊断，不能根据 label 猜 FieldKey。
- 发布请求明确目标客户端集合、ExpectedDraftRevision 和绑定修订；所有产物从同一已锁定输入生成，禁止读到并发修改后的混合版本。记录 Full.NET 适配器/编译器版本、组件注册清单及实际 Renderer 构建摘要，不能只记录上游提交。上线部署核验活动版本所需运行产物：当前实现可直接升级并重验相同投影；不能满足时显式阻断相关发布/办理并诊断，不静默使用最新版解释。只有实际活动版本需要时才保留对应产物，不为假定兼容建设多版本引擎。
- 将完整设计能力与业务发布/客户端执行能力分别标识。发布错误定位组件 ID、配置路径和目标，不损坏草稿；布局/展示组件不因缺 FieldKey 被当成非法业务字段，未映射业务输入不能直接按 text 放行。
- Web 运行按版本使用原版渲染器及 Full.NET 提交适配；授权字段投影与完整设计资产分开，隐藏字段及敏感默认值不得随完整 JSON 泄露。FieldPatch、只读/必填与租户校验仍由服务端权威执行，不把原版浏览器校验当授权。
- VF-F1 的隔离同时用于正式 Renderer。投影还须处理校验、计算和事件对隐藏字段的依赖：需要未授权值的配置明确诊断，不能把完整表单送入浏览器后隐藏控件。服务器的不可变版本资产可按版本缓存，办理授权投影和提交值不按 FormVersionId 共用缓存；读取重新鉴权，切换用户/租户/任务及策略变化不得复用旧投影。
- 原版演示/预览中使用的上传、远程数据和事件不自动获得生产业务能力。后二开按真实依赖新增 Files、目录、数据源连接器及对应 Workflow 授权，既有权限接续在本批完成；不可执行项明确显示诊断/支持状态。原版完整迁入完成与业务全面接入完成分开记录，不能相互替代。
- 清除被替代的精简加载入口、失效过滤/转换规则及只服务旧子集的治理断言，更新实际来源和 Notices；不可删除历史验证事实来掩盖变化。

**聚焦验证：** 不可变快照、发布与保存竞争、失败回滚、声明目标支持检查、运行产物不匹配诊断；实际支持业务字段的设计到填报提交覆盖数字/字符串同值选项、空值、日期范围和精确小数边界，未支持形态明确拒绝发布；直接 API 越权、隐藏字段及其依赖不泄露、不同办理人投影不串用、未知 Patch 拒绝。新增 DTO/SQL 保持 Host.Api AOT 静态闭包，按实际改变的 API/数据路径做双库及 Native 验证。
