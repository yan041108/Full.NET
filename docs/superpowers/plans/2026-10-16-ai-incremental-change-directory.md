# AI 增量变更目录实施计划

**Goal:** 所有者分页发现已可靠确认的最新文档来源，并进入既有索引对账与显式恢复流程。

**Architecture:** AI 自有表内只读 JOIN，SQL Server/MySQL 同场景 keyset 分页；独立精确读取权限、可信 Host/Tenant 范围及等待后的权威复核。Vue 复用既有索引对话框，目录记录不代表待执行任务、收费授权或完整索引就绪。

**Tech Stack:** .NET 10、Dapper、System.Text.Json 源生成、SQL Server/MySQL、生成 TypeScript 客户端与 Vue。

## 执行边界

- main 基线 `42d6714ee48ed58447fe608b7122089f1e58bd55`，快照 `ai-incremental-directory-20261016`；本会话连续开发，保护既有改动，不推送。
- 只读 `fn_ai_*` 当前所有者、启用目录、非墓碑文档、意图及最新已完成来源；不迁移数据，不改变事件、账本或任务。
- 新增独立 `ai.knowledge_documents.index_changes_read` 权限，并同时要求知识库、文档、版本和索引读取权限。普通成员没有所有者目录访问权。
- GET 只接受文档游标及 1..50 的页大小，读取上限为页大小加一。每页固定查询次数，禁止逐文档查询或无界扇出。
- 每次等待后复核可信范围。首次读取、所有者读取后及首轮来源页读取后复核当前会话权限，最后一次通过作为本页读取准入截点；其后撤权不追溯取消已准入页，下一请求重新鉴权。准入后再读所有者/知识库版本与同一来源页，禁用、删除、最新来源变化及租户切换保持失败关闭，不承诺跨模块权限和来源的原子快照。
- 页面称“已确认来源”，不把意图表当作待执行队列。进入既有索引弹窗后重新读取权威状态；费用操作仍使用已有权限、原会话和显式确认。

`AiKnowledgeIndexChangeContracts.cs` 定义最小公开目录；`AiKnowledgeIndexChangeSql.cs` 定义有界、双库且同范围的 SQL；`AiKnowledgeIndexChangeService.cs` 负责权威复核与分页。既有增量 Endpoint、AiModule、权限目录、静态行读取器与 JSON 上下文承载集成。
