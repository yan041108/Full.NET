### 2026-10-26：组织关系与树并发边界

关系两端必须采用相同组织归属模式；关联主端存在性及级联同时限制可信租户和当前实体的组织。Tree 父节点和祖先不能跨组织。ManyToMany 要求两个不同物理外键，且每条关系的复合唯一键恰好覆盖关联对。

Tree 迁移草案增加 `{entityTable}_tree_guard`，表名须保留共同长度预算。每个租户一行；SQL Server 通过唯一键上的 `UPDLOCK/HOLDLOCK`，MySQL 通过唯一键的原子写取得事务互斥。环检查与结构写入共享锁并在提交/回滚时释放；父节点有活动子节点时拒绝删除，避免悬挂引用。该策略仅保护生成服务路径，不声称绕过服务的人工 SQL 也受同一守卫约束。

12 项聚焦测试通过、零跳过，其中 4 项为 SQL Server/MySQL 的独立连接反向重挂并发和组织边界：两个节点同时互设父节点仅一次成功，另一次稳定 parent_cycle；父节点删除被阻止。组织测试的写授权替身允许两个组织，实际数据库仍拒绝跨组织父节点及关联，级联不修改模拟的另一组织坏数据。另外覆盖前述 4 项断言修订、CLI UI 输入、关联复合键、生成夹具一致性，以及新发现的无变更操作终态缺陷：没有暂存目录时完成不应删除不存在的暂存文件；真实 CLI 遗留操作已用 recover 成功恢复。

扩展后的原生探针正在发布及双库复验，尚不计通过。关系页面、主从组合事务与关联维护仍在实施，不能把 Tree 写入守卫视为第四批完成。
