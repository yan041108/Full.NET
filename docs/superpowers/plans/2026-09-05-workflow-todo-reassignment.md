# 工作流活动待办改派实施计划

## 目标

在现有 `workflow.instances.recover` 高权限控制面下增加活动待办改派能力。管理员只能把当前作用域内的活动实例待办改派给同一可信作用域内的活动用户；实例、待办、动作回执、执行轨迹、B0 领域审计与待办通知 Outbox 必须在 Workflow 本地事务中原子提交。

## 本轮范围

1. 增加 `POST /api/v1/workflow/instances/{instanceId}/reassign` 契约并接入精确权限。
2. 在事务外通过 Identity 最小批量目录校验目标用户，禁止 Workflow 跨模块查表或在事务内调用 Identity。
3. 使用实例修订号、待办修订号和幂等键处理并发与确定性重放。
4. 记录 `todo.reassign` 执行轨迹和 `instance.reassign` B0 审计，并原子发布新的 `TodoAssigned` 事件。
5. 补齐错误资源、Native AOT JSON 元数据、模块注册、单元测试、测试矩阵和能力状态记录。

## 非目标

- 不实现暂停实例的强制恢复、步骤回退、超时扫描或任意历史节点跳转。
- 不改管理端页面；页面级联调继续按用户确定的功能优先策略延后。
- 不新增表或迁移；复用现有动作回执、执行轨迹、领域审计和 Outbox 结构。

## 验收

- 非活动或跨作用域目标用户在事务开始前失败。
- 非活动实例、无活动待办、同办理人及修订冲突不产生持久化副作用。
- 成功改派只更新一条活动待办并推进一次实例修订，写入动作、轨迹、审计和一条待办通知事实。
- 同一操作者、幂等键和请求摘要可确定性重放；键复用但语义不同返回冲突。
- 聚焦单元测试、Release 构建、命名/AOT/治理静态门禁通过；双库与 API 重型验证留给取得提交推送授权后的 GitHub Actions。
