## 连续实施

1. P1 Workflow：扫描按提供程序使用有界稳定排序，源查询排除已有 pending/failed/dead_lettered 占用；保留插入端并发去重。扫描调度与消费解耦，满扫描批次继续发现，扫描完成后按间隔复查，已有消费积压不反复触发全扫描。
2. P1 Identity/AI：在现有消费方公开契约增加集合授权，一次校验会话、可信租户与权限快照并验证全部权限。单权限入口复用同一实现。AI 只合并同一校验点内的权限集合，保留收费前、来源读取后及输出前的全部重新授权边界；不引入跨边界缓存。
3. Notifications：MaxConcurrency 接入有界投递，默认保持 1；并行项使用独立 DI Scope 和事务执行器，不共享 DbSession。领取、准备前/外发前租约核验、Provider 超时、终态代次比较和取消语义不变。
4. Regions：树查询在双库 SQL 中限制子树与深度，并设置返回规模上限；超限明确失败。Vue 管理树改为调用现有 children 接口逐层加载，保留操作权限、错误呈现与刷新一致性。
5. Document/ImportExport/Reporting：使用实际领取/处理数量决定轮询；满批立即继续，未满等待 Poll，异常仍退避，动态配置保持有界。

关联实现和回归用例连续完成后集中测试，不把单个文件或步骤变成提交、确认或完整验收检查点。

## 验收与性能证据

- Workflow：大候选集只返回配置批次、已有占用不重复入队、重复扫描无额外写入、消费满批不触发已完成扫描、并发扫描不重复占用；SQL Server/MySQL 同场景。
- Identity/AI：四权限集合只读一次会话和一次权限快照；任一权限缺失、租户不匹配、会话撤销、取消与容量拒绝仍失败关闭；长操作重验仍能观察撤销。
- Notifications：默认串行、配置并发实际生效且不超上限、不同作用域无事务串扰、过期/被抢租约不发送、取消停止后续外发；真实双库回归。
- Regions：局部子树不读取无关节点、深度截断、超限与根查询；浏览器只请求可见层、展开加载子层、编辑删除后刷新无旧节点。双库、Vue 单测、构建与对应页面交互。
- Worker：满批/未满/空批/异常/动态配置/取消的轮询边界。
- 集中运行受影响 Release Unit、Architecture、Node 治理/命名、Vue 回归与构建、必要真实双库、API/Worker AOT 分析及对应 Native 门禁。新增测试数以矩阵维护并运行规定分区/治理门禁。
