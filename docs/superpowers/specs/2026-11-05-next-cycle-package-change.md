# 下周期换套餐

本规格落实产品化计划 F12-R2 的套餐调整差集，沿用同套餐手动续期的当前已履约周期、租户根锁及独立账单。当前底座采用明确的周期末切换政策。

## 周期与资金

1. 来源为活动企业在 Enforced 阶段内当前有效的已履约付费周期，状态可为 Active 或仍在付费周期内的 Cancelled。Trial、未付款、已退款及到期记录不能提出新的下一周期调整。
2. 操作人显式选择另一个当前活动套餐，读取其当前发布报价；下一周期开始时间固定为来源周期结束时间，期限、价格、商户和限额按新报价独立冻结。源套餐可已退出销售，但原付费事实、周期和来源版本仍必须有效；退出销售不恢复原套餐的当前访问资格。
3. 每个企业最多一笔未来非终态订阅，与同套餐续期共用冲突边界。创建时根锁内重验来源版本/周期、目标套餐/报价及其他记录；新订阅持有目标套餐，来源 ID/版本继续保存在原账单结构中。
4. 新旧周期使用独立订阅、账单和支付身份。原周期保持原价格及期限；新周期按完整的新周期报价付款，不抵扣旧周期金额。取消和退款分别沿各自原订阅/订单处理，取消本身不产生自动退款，不做比例结算或资金级联。
5. 付款后仍按原可靠履约队列等待周期起点。只有新周期真正履约才绑定新套餐、授予新来源权益和替换限额；UsedValue/ReservedValue 保留，新上限不足时保留存量并由既有准入停止新增。
6. 原请求摘要已包含目标套餐和报价版本，未知结果保留原来源、目标、时间与幂等键重放；已接受请求的来源后来变更不使其变成新请求，不同目标复用同一键为冲突。

## 契约与管理端

复用续期预览 GET，增加可选 targetPackageId；未提供时仍读取同套餐。响应明确给出 SourcePackageId 与目标 Offer，目标必须是活动套餐。原付费创建正文继续使用 PackageId 表示目标套餐、RenewalOfSubscriptionId/RenewalSourceVersion 表示已核验的原周期，不新增持久化列或独立资金接口。

预览使用订阅读取和套餐读取，创建使用现有订阅管理精确权限。历史行增加“下周期换套餐”，显示原来源及原套餐标识，选择其他活动套餐，显式读取提案后以只读目标展示新价格/期限/限额和固定起点再确认。更换目标先显式清空旧提案，再重新选择和读取。结果不明按原请求恢复；身份、来源或模式变化失效旧草稿。同套餐入口继续固定原套餐，原套餐停用时只能迁往其他活动套餐。

## 验收

有独立配额读取权限的 Host 管理员，可在尚未提交账单的报价确认态显式读取当前账面用量与预留，对比该报价新上限。仅比较读取时点，不承诺未来准入、修正计数、释放预留或阻断已有账单恢复；未知指标不视为零，精确差额使用 BigInt。401/403/404 清空旧快照，暂时故障显示旧成功时间；企业、报价或权限变化取消并清空。普通续期、无配额权限及原请求恢复不自动读取。

报价金额、席位和存储限额及账单创建 HTTP 金额均使用规范十进制 Int64 字符串；报价编辑和影响预览支持完整 Int64，不以浏览器安全整数上限截断。进程内支付 Port 继续传递 long；外部渠道的实际金额准入保持原职责。

集中覆盖双库原套餐退出销售后仍可迁往活动新套餐、停用目标拒绝、报价/来源/周期冲突、同套餐与跨套餐共用未来周期名额、未知结果幂等、周期前不改变套餐或配额、周期后目标绑定及低限额保留用量、旧退款不撤销新来源，以及桌面/窄屏提案和原请求恢复。只运行本次及直接受影响边界，保持外部渠道认证与容量状态的原验证范围。
