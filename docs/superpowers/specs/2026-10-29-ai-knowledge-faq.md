## 完整功能与成功场景

### 受控传输的权威边界（2026-10-30 实现，最终验收见交付记录）

先前验收的 `faq-transfer-v1` 每包最多八条、规范 JSON 最多 512 KiB，保存准确 FAQ 根/修订、内容及来源摘要、独立依据或全部文档叶。当前父图关联实现演进为 `faq-transfer-v2`，新增父节点准确来源及有向边，v1 不作为兼容权威；父图运行验收仍在进行，不能把旧传输证据当作新协议已通过。包只是当前服务器记录的快照，导入必须在同一实例和当前可信租户重新读取原记录、逐字段比对并核证全部依赖；外部实例、未知来源、被编辑或缺失的来源不能导入。

导出有独立权限，并按根及全部叶的最严格分类检查宿主 `export` 数据策略，最终来源复核绑定当前知识库版本和分类。导入同时需要独立 Import 与草稿 Write 权限；跨库目标分类不得低于服务器重新推导的原来源分类，独立 FAQ 也不能通过低分类目标重新定义权威。预览和逐条提交均执行此检查，提交按固定顺序锁定源、目标库根并复核版本/分类，等待期间改变策略则不写入。包内不接受客户端声明的分类授权。

显式预览冻结包摘要；逐条请求键保证原请求重放，每条独立事务、报告部分失败，不自动重试、索引、审核或发布。导入复制服务器不可变修订和完整来源，不创建 Files 对象、不调用模型。正式 Vue 提供有界 JSON 文件/粘贴、选择导出、下载前重新核证、预览与逐条结果及草稿入口；来源或分类拒绝清空包正文，作用域切换/关闭使迟到响应失效。

维护者在知识库内创建标准问题、同义问法、答案、分类及有效期；编辑产生不可变修订。页面同时显示来源类型、编写依据、当前发布和待审修订，草稿/索引处理成功不能冒充发布。审核绑定准确的内容、全部来源、索引代次与有效期，审核后任何变化均须重新审核。已发布旧版在新稿处理、失败或驳回时继续服务；撤销、到期及来源失效拒读，不自动回退旧版。

从已有文档、已接受回答、反馈或派生 FAQ 创建的内容始终为派生类型，来源由服务器读取并冻结。人工改写答案、复制、恢复历史、重新审核或重新发布都不能清空来源或改成独立权威。独立权威使用独立创建入口，必须登记内容所有者、独立出处/编写依据并审核；不能用一个来源类型下拉框将派生条目原地转换。

真实用户流程包括独立创建及审核、从现有回答/反馈转草稿、文档依赖失效、重复同义问法处理、批量导入导出，以及在普通搜索和问答中使用当前有效的 FAQ。AI 内容只进入草稿；初始转草稿复用已有回答，不额外调用模型。未来确需生成时仍走现有明确收费、预算、未知用量、无自动重试及批准模型边界。

## 权威状态、修订与索引

FAQ 主记录绑定知识库、可信租户和一个 AI 自有文档身份。不可变修订保存问题、同义问法、答案、分类、有效期、来源类型、独立编写依据或完整派生谱系；审核与发布指针绑定修订及内容摘要。需要的关系落在 AI 自有表，通过应用端 UUID v7、Dapper 参数化 SQL 和成对 SQL Server/MySQL 迁移实现。迁移编号在落地时核对当前共享工作区，不能预占其他会话的编号。

索引内容从服务器已冻结修订生成，问题/同义问法与答案保持可定位的确定性结构，不接受客户端上传的“已审核索引正文”。复用现有准备、完整代次、预算、失败恢复及发布治理。FAQ 修订与发布的文档身份必须有不可变关联；普通文档上传、编辑、恢复和发布入口也要识别这种关联，禁止通过文档端点绕过 FAQ 来源和审核约束。

FAQ 正文的物化还须覆盖 Files 边界：不能把派生答案写入普通 Host 文件后，仅限制 AI 原文入口，却仍允许普通文件下载/预览交付正文。实现时使用明确的私有资源存取契约，或以静态来源类型适配数据库内的不可变修订；没有文件时不能伪造 FileId 或套用已完成普通文件导入的证明。既有原文文件可能有独立的持有关系，FAQ 拒读不等于撤销其文件引用，读取授权与清理引用必须分开判定。

当前选择静态数据库修订适配：版本的 `FileId` 与 `FaqRevisionId` 严格二选一，服务器生成 `faq-revision-text-v1` 确定性 UTF-8 正文、规范摘要及字节数，不创建 Files 对象或普通导入记录。来源冻结修订、完整依赖、最严格分类、知识库版本和含目的地的精确模型批准。普通文档排除条件保留，公开正文只走准确 FAQ 修订及当前有效发布证明。

Worker 按任务原会话核对当前角色、机构和完整来源绑定；Identity/Organization 只新增既有只读 Port 的最小后台注册。阶段绑定检查不交付正文，也不代替载荷证明。正文读取、模型客户端创建后的收费派发门禁、生成后及结算后返回仍核证实际全部叶载荷，随后再次检查当前权限和来源身份。不存在权限缓存或跨阶段授权令牌；既有 25 秒阶段期限、租约、独立结算、无自动收费重试和所有普通来源路径保持。该布置针对本批真实 Worker 重复核证导致的超时，尚不声明性能或容量指标提升。

本批真实并发还捕获了 MySQL 完成证明死锁：人工来源在事务前使用带锁载荷查询，先占任务再等待文档；完整证明事务已持文档根并等待任务。载荷预读改为先在受跟踪的短事务内取得文档根，再读取单批载荷，释放后解析字节；原最终完整锁证明保持。文档格式的最后授权后复核同样补齐根锁。定向用例以独立连接持有根锁，观察真实数据库等待，确认任务行仍可取得，再验证取消排空；不通过放宽权限、延长期限、忽略载荷或自动重试处理死锁。修复实现和新验收仍以交付记录的实际结果为准。

FAQ 发布指针与索引发布必须在同一 AI 模块本地事务中推进，相关根锁顺序固定。外部授权、Files 和完整依赖证明在事务外完成；事务内最终核对修订、审核、来源快照和候选代次。不能先发布 FAQ 再用补偿猜测另一指针是否成功。沿用失败 Result 回滚、幂等请求键和并发版本，不引入跨模块事务。

同义问法规范化使用一个明确的服务器算法与版本，绑定知识库和可信租户。当前发布条目对规范化问法建立明确的唯一占用；草稿可以表达冲突，发布时不能静默覆盖其他 FAQ。答案不一致、同义问法碰撞及已知制度冲突进入维护者处理。FAQ 不自动获得高于制度文档的排序分数，也不无条件覆盖相反来源；语义质量和真实模型效果继续归 A02。

## 完整依赖与不可降级证明

来源模型明确区分独立权威、文档派生和后续允许的已知派生类型。公开创建请求只提供服务器可重新读取的来源身份；类型、来源谱系、主体绑定、分类、发布身份和生成证据均由服务器推导。未知协议、缺少依赖、仅有引用子集或当前不可读时拒绝创建/发布。

从父 FAQ 派生时同时保留父 FAQ 的准确修订/发布和全部叶来源，不能只展开叶文档后丢失父 FAQ 的当前服务资格。执行有限深度、有限节点的无环证明；超限拒绝整次操作，不能截断依赖。复制和导入不会沿用外部包声称的授权，必须在目标租户重新读取全部当前身份；跨租户、不认识的来源或缺失父节点不能进入发布或检索。

2026-10-30 父图关联实现采用平面图协议：不可变来源 v2 / `faq_derived`，最多四个祖先节点、祖先深度四层、祖先与文档叶合并最多八项，并保留 16 KiB 来源 JSON 字节预算。节点保存准确修订、发布及完整代次，边仅引用本图节点；拒绝环、孤点、缺边节点、自引用、冲突身份及超限，不截断。公开图不返回内部租约或模型凭据。含父图答案使用完整谱系 v6，v5 仅保留原有独立/文档派生语义。候选、收费前预检及持久答案均核对聚合证明预算，来源证明不自动成为候选正文。独立节点核证与完整图门禁分离，索引按任务原会话授权；检索和历史最后一笔联合查询同时绑定所有父发布、精确模型目的地及来源库版本/分类。本批已通过 Unit 104/104、双库实际 Native API 同轮 2/2（受控 JIT Worker）及正式桌面/移动第三轮同轮 2/2；原 HTTP 期限失败与前两轮页面夹具错误均保留，详见交付记录。

实际父派生索引出现阶段内重复加载大快照、耗尽 25 秒期限的问题，父节点增加服务器已完整校验的发布版本与快照摘要作为不可变来源身份。阶段绑定只重读当前模型和分类，并以最后联合 SQL 核对准确发布摘要、版本、完整代次、租约、全部来源和当前权限；它不返回正文，也不授予下一阶段权限。正文读取、收费派发及交付的完整证明仍重新读取并校验父发布快照、确定性修订正文和实际索引载荷。原期限、续租边界、未知用量及无自动收费重试保持；没有增加权限缓存或延长阶段预算。单次捕获库分类仅覆盖该父节点自身全部叶与祖先，不能把同批无关节点的分类混入。

### 反馈转草稿接续边界（2026-10-30 本地聚焦验收通过）

入口从已批准的当前反馈出发，绑定反馈版本、审核版本、原消息/所属会话与可信租户、完整答案谱系及内容摘要。来源必须由服务器重新核证全部依赖并推导，不能使用客户端答案或展示引用子集；编辑、复制、恢复、重发及传输都保留该不可变绑定。反馈撤回、审核变化、原答案或来源失效后，各入口重新拒用，不能以一次批准作为长期授权。

既有反馈审核列表只交付结构化标签，不能把其 Read 权限默认为私人回答正文读取权。转草稿使用独立的窄用途权限和显式预览；服务器复用原回答生成初始草稿，不返回原用户问题，也不调用模型、自动索引、审核或发布。人工填写标准问题及分类，后续编辑追加修订。没有完整可用的谱系或正文超限时拒绝，不截断后继续。

私人回答的派生不得仅按文档叶推断为低敏内容，初始分类以 restricted 为下限，目标库、复制和传输同样不得降低这一来源限制。发布仍需现有独立人工审核及完整来源证明。通用门禁以静态反馈绑定读取当前反馈/审核/消息资格，避免通过再次调用完整历史服务形成 FAQ 门禁的 DI 环；最后资源 SQL 联合核对反馈、叶与父节点。业务来源仍等待 K06。

2026-10-30 关联实现使用来源 v3 / `feedback_derived`、私人直接或继承来源的答案谱系 v7，以及 `faq-transfer-v3`。新增精确权限 `ai.knowledge_faqs.feedback`，同时约束显式预览、私人 FAQ 读取、父图和历史，不把结构化审核 Read 扩大为私人正文访问权。公开预览只返回当前原回答、准确反馈/审核版本及完整来源，人工填写标准问题、分类与有效期；创建请求没有答案或客户端引用字段。摘要绑定操作者、目标库版本/分类和服务器完整来源，目标必须由操作者管理且为 restricted；闭合来源内部保留原消息、所属会话/人、租户和回答/谱系的提供程序精确摘要，公开来源不交付所属人、会话或原用户问题。

候选 SQL 在读取正文前检查当前私人来源权限与严格分类，完整解码进一步核对由实际绑定和父节点推导的私人标记；标记、父关系或来源类型删除均拒绝，不能使用旧谱系隐藏私人来源。写事务取得固定顺序根锁后，最后联合 SQL 再核对目标版本/分类、全部叶、父发布和反馈/审核/原消息资格。正文仍只存在数据库静态不可变修订，不创建 Files 对象；预览和转草稿不调用模型、不自动索引/审核/发布。346 双库约束迁移及部分恢复、公开接口/SDK/Vue、撤回/审核变更、历史及根锁等待均已完成本地聚焦验收。实际 Native 采用原 SQL Server 通过与 MySQL 单独补验，覆盖两个唯一提供程序、各含 Host/Tenant，不称同轮 2/2；正式桌面/移动第三轮同轮 2/2，全部 axe、键盘、撤回清空和四截图核对通过。原令牌过期、对比度/动画和补验前失败保留，K04 整组完成，具体输入及范围见交付记录。

反馈来源最终联合 SQL 的 MySQL 候选分支使用唯一 FAQ 根及准确反馈绑定的单行聚合。隔离的 8.0.46 环境实际出现相关存在性谓词在默认半联接改写后误返回空集；同一绑定在单独谓词及仅诊断连接关闭半联接时均有效。聚合阻止该改写，依赖 ReservedDocumentId、反馈、审核、消息主键的唯一性，保留全部租户、权限、分类和摘要检查；没有修改数据库全局或生产连接设置。适用转换条件参见 [MySQL 8.0 官方半联接说明](https://dev.mysql.com/doc/refman/8.0/en/semijoins.html)，本批修复的依据是保留数据库中的实际复现与公开 HTTP 补验，不把官方机制说明当作该实例缺陷的证明。SQL Server 保留原存在性语义。

候选范围与依赖证明分开表达：用户选择哪些文档参与排名，不等于允许把依赖正文加入模型上下文。FAQ 所有生成依赖参与权限、分类和来源核证，但未选中的原文不得因依赖关系而自动成为候选正文。`SearchScope`、搜索命中、完整快照和答案谱系已增加能够绑定 FAQ 原始类型及完整依赖的静态协议，不能把 FAQ 当作一个没有来源的普通文本文件塞入旧协议。变化采用当前开发底座直接演进规则，同步更新 SDK、Vue 和直接消费者。

后续检索关联批次须保留普通文件查询的 FAQ 排除条件，以独立的、显式 FAQ 发布分支合并候选；不能通过删除 `AiKnowledgeOrdinaryDocumentSql.Visible` 把修订伪装成文件。该分支必须同时绑定 FAQ 身份、不可变修订、内容/来源摘要、当前发布及完整索引代次，并在实际载荷证明和最终权限重读后交付正文。FAQ 修订位置按其自身文本协议标识，不能生成原文件下载链接或伪造原文坐标。公开搜索来源、冻结问答输入、引用及持久答案谱系同步演进为静态闭合类型；来源识别失败或字段缺失时拒绝，不能回退到旧文件协议。

完整谱系须区分参与排名的 FAQ 节点与仅用于证明的叶来源。持久历史保留每个 FAQ 节点的准确修订/发布及全部叶依赖，历史、继续对话、反馈转草稿和导出重新核对当前服务资格；不能只展平文档叶而丢失父 FAQ。父节点关系只来自服务器读取的当前发布，执行有界深度、节点及总依赖预算并检测环；超限时拒绝整次，不截断后继续。普通检索与 FAQ 候选共享同一总候选预算、租约、批准模型和目的地、原操作预算及最后派发/交付复核，不因 FAQ 分支自动调用模型或改变基础排序策略。闭合来源、有界多级父节点图、完整答案谱系及父图传输已有本地聚焦证据；反馈绑定关联实现与真实栈验收也已完成。

## 公开操作与页面

在 `Features/ManageKnowledgeFaqs` 下形成关联用例，由传输层映射强类型请求/结果和标准 ProblemDetails。创建、修订、读取、审核、发布/撤销、从回答/反馈转草稿、导入和导出使用稳定独立权限；同时要求对应知识库/文档读取或维护权限。超级管理员不绕过租户、来源或会话证明。操作码在实现时按 Naming Profile 统一登记，不在设计中生成未消费的公共接口。

Vue 唯一交付线在现有知识管理区域增加 FAQ 列表和编辑/审核流程，显示当前发布、草稿、来源身份、有效期、同义问法冲突与审核状态。派生来源只读，恢复或复制后仍可核对原始类型和全部依赖。依赖失效、版本冲突或会话切换时清空旧敏感正文；导入先预览实际拒绝/冲突项目，再明确提交。所有正文按文本渲染，不执行模型 HTML。

批量传输采用有版本、严格字段和有界总量的公开包，保留修订类型、全部依赖、有效期和冲突语义。导入使用内容摘要与幂等键，逐条处理的原子性和整包报告须明确；失败/未知不记为成功，重放不重复建立条目。独立手工包也须进入独立依据及审核入口，删除来源列、伪造类型或导出再导入不能绕过来源审核。导出本身执行当前读取、全部来源及宿主数据策略核证。
