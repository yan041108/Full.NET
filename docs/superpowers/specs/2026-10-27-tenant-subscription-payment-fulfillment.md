# 订阅支付履约

日期：2026-10-27。状态：本地限定范围验收通过。范围为接替开发的非 Workflow SaaS 支付能力；复用现有 Payments 渠道及 Tenancy 权益、配额边界。证据见[接替开发记录](../../verification/2026-10-27-non-workflow-delivery.md)。

## 所有权与发布闭包

- Tenancy 拥有套餐报价、冻结订阅、订阅来源权益和配额；Payments 拥有商户、订单、回调、退款及资金事实。禁止跨模块写表、外键或事务。
- 既有 `Tenancy.Contracts` 增加 `ITenantSubscriptionBillingPort`，实际消费者为 Payments API/Worker，提供方为 Tenancy。Payments 已依赖 Tenancy，不引入反向运行时依赖或新项目。
- UI/普通 HTTP 不提供“外部支付引用即激活”入口；旧测试履约占位不作为生产资金证明。人工授权与付费履约分开，人工管理仍须精确 Host 权限和审计。

## 报价与创建

1. Host 在套餐上发布有版本的报价，冻结金额、币种、收款商户及其所属租户、功能权益和席位/存储限额；维护报价同时要求套餐更新和权益绑定权限。收款租户与受益租户分开，支持平台商户向业务租户收款。
2. 付费订阅以期望报价版本创建，保存不可变报价和独立 PaymentOperationId，初始 PastDue，不提前授予功能或扩大配额。付款请求只接受订阅身份，金额不能由浏览器覆盖。
   有效天数由报价固定（1–3660 天），浏览器不能自定结束时间；开始时间统一到双库共同的微秒精度。套餐名称作为原订单标题保存，后续报价修改不改变已经冻结的金额、期限和权益。
3. Payments 先保存本模块履约关联，再通过现有幂等订单服务调用渠道；没有支付事实时不授予权益。创建中断可用同一报价/幂等键重试，不自动发起新扣款；未知渠道结果沿用已有对账入口。

## 可靠履约与退款

1. 支付及退款状态变更与重要事实 Outbox 同事务提交。Payments 消费只登记本模块工作项，跨模块 Contract 在独立后台事务外调用。
2. 工作项绑定受益/收款租户、商户、支付创建身份、实际订单、金额和币种。重复通知不重复授予，乱序退款不得被迟到支付覆盖。租约、重试、退避和人工处理状态持久化。
3. Tenancy 再次比对冻结报价、订阅状态/期限及事实，在本地事务一次性激活订阅、创建带 SourceSubscriptionId 的功能绑定并更新配额。成功响应丢失后只重放原履约结果。
4. 新配额预留/确认及功能判断校验来源订阅有效性。到期、取消期末生效或退款后限制新增；既有业务数据、已用额度、独立人工授权和其他订阅不被清空。退款事实使原订阅进入待核对状态，原自动授权不再有效，不以全局禁用租户代替商业政策。
5. 未到生效日不提前授予；已过期、取消竞争或资金绑定不符进入人工处理。当前套餐/目录停用仍拒绝发放，正常报价更新不撤销旧冻结条款。重试只能重放同一资金事实，不得复活已被终止的旧订阅。
6. 首版成功退款撤销原订阅自动授权资格，包括部分退款；不实现按比例保留权益。原订阅进入 PastDue 后需显式取消/核对，不能用迟到付款重新激活。

## 验证边界

聚焦覆盖报价篡改、跨租户/商户、重复和乱序支付/退款、资金成功但履约失败、响应丢失、租约竞争、到期与取消、权益来源隔离及双库回滚/恢复。使用现有测试渠道替身与正式验签/持久化链路，不用真实商户执行测试扣款。

不包含自动续费扣款、按比例计费、发票和税务承诺。真实渠道认证、容量或生产可用性需独立证据；本地功能验收不能升级这些状态。
