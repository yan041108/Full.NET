# Full.NET 项目规则治理设计

日期：2026-07-17  
状态：已批准（依据项目所有者“后续自动确认，按推荐方案执行”的授权）

## 1. 背景与目标

Full.NET 将长期迭代为可快速开发产品和交付项目的基础框架。随着模块、数据库提供程序和基础设施能力增加，仅依赖一次性的开发计划容易遗漏跨模块约束，也无法让后续开发稳定复用已经验证的经验。

本设计建立一套能够被开发代理自动发现、由项目维护者审查、并可持续演进的仓库级规则体系，目标是：

1. 明确代码注释的质量标准，确保关键设计意图、约束和风险可维护。
2. 将开发中高频遗漏转化为可执行的检查规则。
3. 在每项任务结束时自动进行遗漏复盘，但避免无边界地追加规则。
4. 让规则变更与代码变更一样可审查、可追溯、可验证。

## 2. 方案比较

### 方案 A：只创建 `rules/`

优点是结构清晰；缺点是多数开发工具不会自动读取自定义目录，规则可能存在但不生效。

### 方案 B：只创建根目录 `AGENTS.md`

优点是可自动发现；缺点是所有细节集中在一个文件后会快速膨胀，增加上下文成本，也不利于按主题维护。

### 方案 C：`AGENTS.md` 入口 + `rules/` 模块化规则（采用）

根目录 `AGENTS.md` 只保留最高优先级约束、任务工作流和规则索引；详细规范放入 `rules/`。开发代理进入仓库后先读取入口，再按任务类型加载相关规则。

## 3. 文件结构

```text
AGENTS.md
rules/
├── README.md
├── code-comments.md
├── development-quality.md
└── rule-evolution.md
```

- `AGENTS.md`：自动发现入口，定义必须执行的任务前、任务中和任务后流程。
- `rules/README.md`：规则目录、优先级、适用范围和维护约定。
- `rules/code-comments.md`：C#、SQL、配置与文档中的注释标准。
- `rules/development-quality.md`：由当前项目经验提炼的遗漏防护清单。
- `rules/rule-evolution.md`：经验候选、升级门槛、冲突处理和退役机制。

## 4. 注释策略

“清楚完整”不等于逐行解释语法。注释应优先解释代码无法直接表达的原因、边界和不变量。

必须注释的内容包括：

- 对外公开的 API、扩展点和配置项；
- 事务、一致性、幂等、锁、租约、并发和重试语义；
- 租户隔离、认证授权、敏感数据处理等安全边界；
- 跨数据库差异、手写 SQL 的非显然行为；
- 协议、序列化和兼容性约束；
- 有意接受的权衡、临时兼容方案和外部限制。

禁止无信息量的逐行注释、长期保留的注释掉代码、无退出条件的 TODO，以及与实现不一致的过期注释。代码标识符使用清晰英文；所有手写源代码注释（包括 XML 文档注释）统一使用清晰中文，协议名、类型名和行业术语可保留英文。规则与设计文档使用中文。

## 5. 遗漏防护模型

开发完成声明前，至少检查以下维度：

1. 需求、授权和范围是否完整覆盖；
2. 架构依赖方向和模块边界是否被破坏；
3. 安全、租户隔离、并发、事务、幂等和失败恢复是否明确；
4. SQL Server 与 MySQL 是否同时支持，迁移、索引和回滚是否匹配；
5. API、错误模型、Admin.NET 兼容层和序列化契约是否保持一致；
6. 缓存、消息、日志、指标、健康检查和多实例场景是否可运行；
7. 测试是否覆盖成功、失败和边界路径，实际测试运行器是否真的执行了测试；
8. 文档是否区分已实现、计划中和示例能力；
9. 依赖许可证、版本集中管理、密钥和配置是否合规；
10. Git 分支、工作区、换行符和跨平台构建是否干净可复现。

## 6. 规则自我迭代

每项开发任务结束时执行一次“遗漏复盘”，将发现分为三类：

- 单次任务缺陷：直接修复，不自动新增永久规则；
- 候选经验：记录原因与预防方式，等待更多证据；
- 强制规则：满足升级门槛后写入对应规则文件。

满足以下任一条件才可升级为强制规则：

1. 同类遗漏重复出现；
2. 问题涉及安全、数据损坏、租户越权、许可证或不可逆发布风险；
3. 项目所有者明确确认其为长期架构或交付约束；
4. 已有规则表达不清，导致可重复的错误解释。

新增规则必须具体、可执行、尽可能可验证，并包含来源或理由。规则变更不得静默进行：必须出现在 Git diff 中，接受与普通代码相同的审查。不得用项目规则覆盖系统、开发者或用户指令。

## 7. 验证与验收

实施完成后应验证：

- 根目录入口和所有索引链接存在；
- 每项强制要求使用明确的“必须/禁止/应”措辞；
- 规则之间没有明显冲突或重复；
- 规则覆盖当前 Full.NET 的 Dapper、双数据库、ProblemDetails、Admin.NET 兼容、FusionCache、MessagePack、Outbox 和测试运行方式；
- Git 工作区只包含本次规则体系相关变更。
