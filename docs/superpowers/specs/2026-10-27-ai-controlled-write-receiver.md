# AI 跨模块写入受控接收方验证

状态：已完成本地双库定向验证，2/2、零跳过（2026-10-27）。范围为 AI-D02，不增加付款、删除、外发等生产 Handler，不修改 Workflow 模块。

现有测试证明 AI 内部重命名、审批消费与未知工具结果，但未覆盖完整跨模块可靠写链路。本批使用既有重命名审批协议作为固定批准输入，测试内将 Handler 替换为受控发送器；正式授权、审批消费、工具审计、Dapper 事务、Outbox、MemoryPack 和 Inbox 均复用正式实现。模拟接收方拥有独立测试表和本地事务，不与发送方共享事务；不注册进产品工具目录。

发送器在 AI 本地事务内消费原审批，保存发送意图并写 Outbox，返回 accepted，不能把接收方业务未完成记为完成。接收方按 Envelope、原操作身份、主体、目标和批准参数摘要校验，Inbox 与自己的业务修改、操作去重及回执 Outbox 同事务提交。发送方回执消费以原意图身份及摘要匹配，不重放工具、不重新消费审批。

双库验证发送 Outbox 故障回滚、发送提交后响应丢失、重复/篡改投递、接收方业务提交后响应丢失、不同消息身份复用同一操作、回执消费提交故障及重放收敛。测试在隔离数据库直接投递正式序列化后的 Outbox 载荷，不证明真实 Broker、真实多进程中断或云模型质量。原始通过结果登记于非 Workflow 接替记录。

正式 Inbox 的消息身份/载荷摘要和接收方的业务操作身份分别验证：相同消息重投跳过，不同消息引用同一操作仍只修改一次；篡改为自洽新参数也不能复用原消息或操作。回执要求原主体/会话/目标/参数摘要全部匹配，失败回滚后重投仅推进一次，完成不重跑工具。固定六字段 `string[]` 仅为夹具的闭合 MemoryPack 协议，不构成新生产事件契约。场景为 Host 作用域，不外推完整租户/组织矩阵。
