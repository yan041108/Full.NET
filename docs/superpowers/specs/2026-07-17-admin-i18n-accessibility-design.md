# Full.NET 双管理端国际化与可访问性设计

- 日期：2026-07-17
- 状态：已确认
- 决策方式：依据项目所有者“后续自动确认（按推荐方案来）”的持续授权，采用推荐方案
- 适用范围：`packages/admin-i18n`、`ui/admin`、`ui/admin-layui`、`tests/e2e/admin-parity`

## 1. 背景与目标

C1 已完成 Vue 与 Layui 两套管理端的真实登录、会话刷新、退出、可信租户切换、权限导航和状态页，但当前文案全部硬编码为中文，也缺少可重复执行的完整可访问性基线。下一阶段需要在不共享 UI 组件源码、不复制 layuiAdmin 产品资产的前提下，同时补齐两端能力。

本设计的目标是：

1. 首期支持 `zh-CN` 与 `en-US`，中文为默认语言；
2. 两套管理端共享消息键、语言解析和持久化规则，分别实现自身渲染适配；
3. 语言切换无需重新登录，刷新浏览器后保持选择，并同步更新 HTML `lang` 与页面标题；
4. 对登录、工作台、租户上下文和状态页建立相同的 WCAG 2.2 A/AA 自动检查与键盘验收；
5. 明确自动化与人工辅助技术验收的边界，不把工具未覆盖的部分误报为已验证。

## 2. 方案比较与结论

| 方案 | 优点 | 主要问题 | 结论 |
|---|---|---|---|
| Vue 使用专用 i18n 库、Layui 独立维护字典 | Vue 生态成熟 | 两套消息键和语言规则容易长期漂移 | 不采用 |
| 两端共享整个国际化 UI 层 | 复用最多 | 破坏双管理端独立实现边界，并使 Layui 依赖 Vue 语义 | 不采用 |
| 共享无框架消息契约，两端各自绑定 DOM/响应式状态 | 保持业务术语一致，不共享组件源码，依赖轻 | 两端仍需各自完成渲染和测试 | 采用 |

可访问性采用“自动规则检查 + 键盘/焦点 E2E + 人工辅助技术清单”。只加少量 ARIA 属性无法证明完整性；只运行自动扫描也不能覆盖全部 WCAG 成功准则。

## 3. 共享国际化契约

新增私有工作区包 `@fullnet/admin-i18n`：

```text
packages/admin-i18n/
├── package.json
├── tsconfig.json
├── src/
│   ├── index.ts
│   ├── locale.ts
│   └── messages.ts
└── tests/
    └── i18n.test.ts
```

该包只包含以下无框架能力：

- 受支持语言常量 `zh-CN`、`en-US`；
- 严格的消息键类型和两套键集合一致的字典；
- `resolveLocale`：先读取已保存的合法选择，再读取 `navigator.languages`，最后回退到 `zh-CN`；
- `createTranslator`：只接受已声明消息键，并支持命名参数插值；
- `applyDocumentLocale`：更新 `document.documentElement.lang` 和调用方提供的页面标题；
- 固定存储键 `fullnet.admin.locale`。

共享包禁止访问 Vue、Pinia、Layui 全局对象或具体页面 DOM，也禁止返回未清理 HTML。插值结果只能作为文本写入；动态服务端导航仍通过现有本地可信组件白名单，国际化不能扩大其执行能力。

## 4. 语言状态与交互

### 4.1 Vue 管理端

Vue 端新增轻量响应式语言适配器，暴露 `locale`、`setLocale` 和 `t`。语言状态独立于认证会话：退出登录不会清除用户偏好。登录页和已认证顶栏都提供带可见标签的语言选择器。

页面组件、状态页、导航本地目录和客户端生成的错误提示改用稳定消息键。服务端返回的动态名称、租户名称、用户名和稳定错误 `code` 不被翻译；服务端 `title/detail` 只作为未知错误的安全回退，客户端逻辑不得依赖其语言文本。

### 4.2 Layui 管理端

Layui 端通过 `data-i18n`、`data-i18n-aria-label` 等受控属性绑定静态文案，动态内容由现有渲染函数调用 `t`。切换语言时重新渲染当前会话快照、导航和路由状态，但不重新请求 API，也不改变 Hash 路由或认证状态。

DOM 绑定只允许从本地消息键表取纯文本，禁止把翻译内容交给 `innerHTML`。语言监听器必须在应用 `dispose` 时移除，避免测试和微前端卸载后的重复回调。

### 4.3 导航与业务数据边界

当前壳层的本地 `componentKey` 目录增加标题与说明消息键。已知组件使用本地翻译，未知组件继续拒绝；未来可配置菜单需要单独定义可版本化的 `titleKey` 契约，本阶段不把任意服务端字符串解释为本地消息键。

租户名称、账号显示名、TraceId、错误码、版本号和 API 标识使用 `translate="no"` 或等价语义，避免浏览器自动翻译破坏技术标识。

## 5. 可访问性基线

两端必须实现相同语义与行为，不要求 DOM 或像素一致：

1. 页面提供第一个可聚焦的“跳到主要内容”链接，目标为当前唯一主内容区域；
2. 使用 `header`、`nav`、`main`、`aside`、`form` 等原生语义，页面标题层级从唯一 `h1` 开始；
3. 表单控件具有可见 `label`、稳定 `name`、正确 `type` 与 `autocomplete`；用户名关闭拼写检查；
4. 当前导航使用 `aria-current="page"`，装饰图标使用 `aria-hidden="true"`，图标按钮必须有本地化可访问名称；
5. 登录错误、租户切换错误、会话恢复和异步结果使用合适的 `aria-live`/`role="alert"`，不重复播报；
6. 路由切换后更新页面标题，并把焦点移动到新视图的 `h1`；鼠标点击不产生多余焦点环，键盘焦点始终清晰可见；
7. 所有动作使用 `button`，导航使用链接；可点击卡片不得只依赖鼠标事件；
8. 在 320 CSS px 宽度和 200% 缩放下不丢失核心操作，不禁止页面缩放；
9. 动画只改变 `transform`/`opacity` 等合成属性，并遵守 `prefers-reduced-motion`；禁止 `transition: all`；
10. 动态长文本可换行或截断，Flex/Grid 子项允许收缩，空集合展示明确空状态。

视觉方向延续现有 Full.NET 工具型控制台：深海蓝与青绿色信号色、清晰的信息密度和技术控制面气质。国际化与可访问性只优化层级、节奏、焦点和响应式，不复制 layuiAdmin 源码、CSS 或资产，也不把界面改造成通用模板风格。

## 6. 自动化与人工验收

### 6.1 单元测试

共享包测试必须覆盖：

- 两种语言字典键完全一致；
- 非法存储值与未知浏览器语言安全回退；
- 地区语言归一化，例如 `en-US`、`en-GB` 进入英文，`zh-Hans` 进入中文；
- 命名参数插值和缺失参数行为；
- `html lang` 与标题更新。

Vue 和 Layui 分别覆盖：语言选择、持久化、无需重新认证的实时更新、导航与状态页翻译、监听器清理，以及所有翻译以文本方式写入。

### 6.2 Playwright E2E

`tests/e2e/admin-parity` 增加开发依赖 `@axe-core/playwright`，版本锁定并登记为测试工具。它采用 MPL-2.0，但只存在于开发依赖和 CI，不进入 Full.NET 最终发布物；生产依赖许可证清单必须证明其未被分发。

两端用同一场景执行：

- 登录页、工作台、租户上下文、403/404/500 页面无 `wcag2a`、`wcag2aa`、`wcag21a`、`wcag21aa`、`wcag22a`、`wcag22aa` 标签违规；
- 切换到英文后可见文案、`html lang` 和页面标题同步，刷新后保持；
- 纯键盘可从跳转链接进入主内容、完成登录、访问导航、切换租户并退出；
- 路由切换后焦点落在当前 `h1`；
- 320 CSS px 视口下不存在页面级水平溢出，核心操作可见；
- `prefers-reduced-motion: reduce` 下关键过渡被禁用。

不得通过全局排除节点、关闭颜色对比规则或忽略严重度来制造通过。第三方组件确需例外时，必须定位到具体规则、说明用户影响、提供替代措施并建立跟踪项。

### 6.3 人工验收边界

自动化不能替代真实辅助技术。发布前清单必须保留：Windows Edge + NVDA 的登录、导航、错误和租户切换冒烟；浏览器 200% 缩放；高对比度/强制颜色；触屏与键盘混合操作。当前机器未实际执行的项目必须标记为“待人工验证”，不能将 C1 标记为完全 `Verified`。

## 7. 错误处理、性能与安全

- 语言存储读写异常必须静默回退到内存状态，不能阻断登录或路由；
- 未知消息键在开发/测试中抛出明确错误，生产构建不得展示内部堆栈；
- 字典按静态模块打包，首期只有两种语言，不增加运行时网络请求；
- 切换语言只触发必要的文本和当前视图重绘，不重新加载会话快照；
- 翻译参数不得进入 HTML、URL、样式或动态模块路径；
- 稳定错误处理仍以 ProblemDetails `code` 为判断依据，语言切换不改变协议契约。

## 8. 文档、状态与退出条件

实施完成后同步：

- `docs/roadmap/client-delivery-roadmap.md`：将 C1 国际化和自动可访问性基线标为已实现，保留真实辅助技术人工门禁；
- `docs/development/getting-started.md`：增加双端语言与可访问性验证命令；
- `README.md`：更新客户端能力快照；
- `.github/workflows/ci.yml`：保持双端 E2E 包含可访问性扫描；
- 生产与开发许可证清单：明确测试工具不进入最终发布物。

本阶段退出条件：共享契约、Vue、Layui 的单元测试和生产构建全部通过；同场景双端国际化、键盘、焦点、重排和 axe E2E 通过；文档诚实记录仍需人工辅助技术验证。完成后进入 C2.1 首个 Identity/Tenancy/Organization 双端纵向业务切片。

### 8.1 与全栈多语言的边界

本设计只完成 Vue/Layui 管理壳层的自有文案，不覆盖 Element Plus/Day.js 和 Layui 组件内置文案，也不覆盖 ASP.NET Core 请求文化、ProblemDetails/FluentValidation、账号或租户语言偏好、uni-app、Flutter、通知、报表、Realtime 与 AI 输出。后续工作不得扩张本包为跨 C#/Dart 的万能翻译运行时，而应遵守[全栈多语言与本地化设计](2026-07-17-full-stack-localization-design.md)的统一治理与平台原生实现边界。
