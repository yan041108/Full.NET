# 同套餐手动续期

本规格落实产品化计划 F12-R2 的提前手动续期差集。Tenancy 持有订阅、原报价及续期来源，Payments 继续持有资金事实和履约队列；复用现有模块和事务边界，不新增项目或渠道扣款方式。

## 业务规则

1. 仅活动企业、Enforced 预设内已经履约的同套餐可提前续期。来源必须为当前周期内的 Active，或取消续订但当前付费周期仍有效的 Cancelled；来源账单必须 Applied，订阅与账单周期一致。Trial、未支付、已退款及已到期记录不作为提前续期来源，已到期仍走既有新周期购买。
2. 续期产生独立订阅、账单和资金操作，来源 ID 与来源版本持久化。开始时间固定为来源周期结束时间，期限和价格取当前发布报价，不延长或改写旧周期。
3. 一个企业最多有一个未来非终态订阅。创建在原租户根锁内校验来源版本、周期、套餐、报价及其他非终态记录；来源本身可作为唯一排除项。普通新购/试用也不能绕过仍有效的已履约 Cancelled 周期产生重叠。
4. 报价与来源读取只是本次提案；创建时重新验证。固定幂等键和完整原正文，重放先读取既有请求，来源随后取消、版本变化或到期不使已接受请求变成新请求。不同正文复用键仍为冲突。
5. 下一周期的资金、退款和权益来源独立。取消或退款旧周期不会自动取消/退款新周期；新周期退款只撤销新周期来源，不删除业务数据或撤销旧来源之外的独立授权。
6. 未来周期不提前覆盖当前权益或配额；复用付款事实、冻结生效时间及既有可靠履约重试。排期为最早处理时间，不承诺该时刻已经完成。延迟付款不顺延冻结周期。
7. 新周期采用新报价限额，但 UsedValue/ReservedValue 不清零。低于存量占用时保留资源，按既有限额准入停止新增，不默默补足额度或删除数据。

## 契约与持久化

- 新增只读续期预览：返回可信企业、来源 ID/版本、固定生效时间、当前报价与服务器读取时间，使用原订阅读取和套餐读取权限及 no-store。
- 现有付费创建请求可携带成对的 `RenewalOfSubscriptionId`、`RenewalSourceVersion`。普通购买不携带；续期必须绑定预览中的原套餐、报价版本和开始时间，服务端不信任客户端推断。
- `fn_tenancy_subscription_invoice` 增加这两个可空来源列及成对约束，历史普通账单为空。SQL Server/MySQL 同步实现，静态物化、注释、请求摘要与冻结条款同步。
- 候选数量在同模块查询侧精确计算，不跨模块读写表或扩大本地事务。付款/退款、幂等与至少一次履约继续走现有 Contract。

## 管理端

活动或仍在原周期内取消的历史行提供同套餐续期提案入口，最终资格由服务端决定。显式读取当前预览，展示原来源、固定开始、新期限/价格/限额及独立账单政策后确认创建；套餐与开始时间不可改。创建结果不明保留完整原请求，不自动再建或下单。权限/身份变化失效旧提案。

## 验证与范围

按完整功能集中验证：来源资格和版本、其他未来周期冲突、并发根锁、幂等重放、双库来源列部署/部分失败恢复、当前周期不被提前覆盖、到期后新来源生效、退款来源隔离及前端原请求恢复。只执行本次及直接受影响用例，不执行全量。

不含自动扣款、跨套餐升降级、按比例计费/退款或外部商户认证；本地受控渠道证据不提升 `External-auth-not-verified` 或 `Capacity-not-verified`。
