## 1. 决策摘要

Workflow 拥有流程定义、不可变定义版本、表单定义与版本、运行实例、步骤、待办、抄送、表单提交、执行日志与恢复控制面。业务模块只能通过最小 Contract Port 或版本化 Integration Event 启动流程、读取权威状态或接收结果；禁止 JOIN、外键或读写其他模块表。

继续扩展 Full.NET 自有内核，保持模块化单体、Dapper、双数据库、显式状态机、事务 Outbox 与 Worker/Jobs 租约恢复。完整整改目标为参考 Workflow-Vue3 的 18 类可添加节点，加上发起和结束；现有目录覆盖其中 6 类可添加节点，12 类仍缺失，详见 §5.3。子流程、动态路由、受控连接器和跨租户协作已纳入目标。BPMN 交换、替换或引入第二执行引擎仍不在本次范围；如改变长期架构基线，再按 ADR 规则处理。

项目所有者已确认 Workflow-Vue3 可使用且已取得作者允许，其本地改造成果作为树形工作流设计器的交互基础。VForm3 按 §6 先完整迁入源码、设计器与 Web 渲染器，原版功能对齐后再二开。流程 Draft 编译为 Full.NET Workflow IR；完整 VForm 设计 JSON 则作为设计资产独立无损保存，发布时固化设计/渲染快照并生成服务端业务校验模型。设计资产不能替代权限、租户或业务状态的权威判断。

## 2. 已批准的长期决策

1. 定义权威格式为规范 JSON；MemoryPack 只用于需要可靠跨进程交付的 Integration Event，不作为定义数据库列格式。
2. Workflow-Vue3 设计态经服务端编译为单一 Workflow IR；LogicFlow 明确排除，不迁入其设计器、节点、协议适配或轨迹视图。
3. 允许同一业务键保留历史根实例，但同一作用域最多一个占用中的根实例（`active` 或 `suspended`）；批准后重开必须由业务模块显式发起新根实例。子流程使用独立父子执行身份，不竞争根实例业务键，见 §7.1。
4. Reject 保持终态 `Rejected`；现有退回只支持同一实例当前有效执行链上已完成、具有单一办理人快照的人工审批步骤。参考配置中的“驳回到指定节点”在目标协议中映射为独立 Return 策略，不能冒充终态 Reject。增强时按 §8.2 重建新尝试、席位和分支事实；不允许任意历史跳转，也不能自动撤销已经发生的外部副作用。
5. 定义、实例和表单支持 Host/Tenant 双作用域；普通实例禁止跨作用域引用定义、表单、主体或文件。规划中的跨租户审批通过显式协作授权、最小字段投影、目标租户任务和可靠结果回传实现，不能通过关闭租户过滤或信任客户端 TenantId 实现。
6. 当前可执行目录为发起、人工审批、分组审批、办理、投票、领取、抄送、空节点、排他/并行/包容网关和结束；人工审批已支持单人及 `all`、`any`、`nOfM`、比例和依次。各节点只开放运行时已实现的闭合配置；配置级缺口及客户端/AOT 证据仍按连续实施计划跟踪，其他节点保持 Planned。
7. VForm3 先完整原样迁入，保留全部原版组件、布局、属性、预览、工具栏及设计 JSON。设计稿使用独立契约无损持久化，不能只存简化 `WorkflowFormSchema` 后反推回显。Web 使用完整 VForm 设计器/渲染器；脚本及事件等原版编辑和预览能力在隔离 Web 运行域保留，不能删除后声明对齐。服务端业务校验、可信字段策略和跨端协议仍由 Full.NET 控制，uni-app 不引入桌面设计器。
8. 表单能力在只有 Workflow 一个真实消费者时留在 Workflow 主项目内；出现第二个独立消费者后再通过 ADR 评估抽取 Forms 模块。
9. Workflow Todo 是可办理工作的权威状态；Notifications Inbox 只是提醒与阅读状态。统一工作台只能通过 API/UI 组合，不合表、不跨模块 JOIN。
10. 已有 `Full.NET.Modules.Workflow.Contracts` 由 DataApproval、EnterpriseRequest 等真实消费者使用；新增契约继续要求真实消费者，不创建占位 Integration Event 或空 Outbox 写入。

## 3. 目标与非目标

### 3.1 目标

- 定义草稿编辑、校验、规范化和发布不可变版本；运行实例固定绑定启动版本。
- 表单草稿编译、不可变表单版本、流程版本固定绑定、节点字段策略和服务端权威校验。
- 人工待办、单人审批、显式用户会签/或签/N-of-M、抄送、排他条件、终态拒绝、取消、幂等、并发修订和恢复。
- 精确权限码、Host/Tenant 隔离、资源级授权、B0 领域审计和敏感数据边界。
- SQL Server/MySQL 成对迁移、部分 DDL 恢复、Integration、Native AOT 与真实栈验证。
- 与 Notifications、Jobs、Identity、Organization、Files 和业务模块通过明确 Port/事件协作。
- 补齐 §5.3 全部节点及其配置、回显、发布、执行、轨迹、恢复和客户端办理；代理、转办、撤回、工作日历、超时处置、组合条件和可信选择器按关联功能批次实现。

### 3.2 非目标

- BPMN 全量兼容、第二执行引擎、LogicFlow、无约束自由跳转和无界循环。动态路由的目标和回边必须受编译规则、执行预算与恢复语义约束。
- Workflow 服务端执行任意 JavaScript、动态程序集、反射扫描及不受控远程访问。VForm 原版中的脚本、样式、HTML 与事件等设计/预览能力按 §6 完整保留并隔离接入；这不授权其获得后台宿主凭据或成为服务端动态执行协议。
- 任意 SQL、未受控 HTTP 或跨模块表写入节点；受控 HTTP Connector 纳入触发器目标，业务数据修改/删除通过拥有者模块公开的强类型 Business Command，流程自己的字段变更由 Workflow 校验和持久化。
- DataApproval 通用 HTTP 中间件拦截业务写路径。
- uni-app 复用 VForm3、Element Plus 或 Web 动态组件运行时。
- 提前创建通用 Forms、Workflow Engine、Provider 或传输项目。

## 4. 模块边界与依赖

| 依赖 | 边界 |
| --- | --- |
| Identity / Tenancy / RBAC | 会话、租户上下文和精确权限；指派主体来自受信目录，禁止信任请求体中的跨租户 UserId |
| Organization | 通过最小批量 Port 解析组织、负责人和数据范围；Workflow 不查组织表 |
| Files | 表单只保存受控 FileId 引用；提交和读取时重新验证租户、资源权限与状态 |
| Notifications | 待办到达/超时/完成提醒走版本化事件；Workflow 不直写通知表，Notifications 不办理待办 |
| Jobs | 超时扫描和卡住实例恢复只触发 Workflow Command；禁止直接 UPDATE Workflow 表 |
| Auditing | 发布、取消、审批、改派和强制恢复写 B0 领域审计；Audit 不使用 Outbox |
| Messaging | 有真实消费者的重要结果事件与 Workflow 本地状态同事务写 Outbox；消费方 Inbox 幂等 |

Workflow 生产 SQL 只访问 `fn_workflow_*`；其他模块禁止访问这些表。跨模块本地事务、外键、视图、同义词和隐藏 JOIN 全部禁止。

## 5. 定义、设计器与单一 IR

### 5.1 发布链路

```text
Workflow-Vue3 Tree Designer（受限节点目录）
  → WorkflowDefinition Draft
  → 客户端强类型结构校验
  → Publish API
  → 服务端权限 + Schema + 语义 + 安全校验
  → 规范化并编译为不可变 WorkflowDefinitionVersion IR
  → 内容哈希
  → Runtime 只执行已发布 IR
```

每个节点使用稳定字符串 `NodeTypeKey + NodeSchemaVersion + NodeKey + Config`。当前类型键为 `start`、`human.approval`、`notify.cc`、`control.empty`、`gateway.exclusive`、`gateway.parallel`、`gateway.inclusive`、`end`；发布时拒绝未知节点/字段版本、重复 NodeKey、悬空引用、不可达节点、无终点、非法回边和当前部署不可执行的节点。新增类型键及具体配置在对应实施批次固化，参考项目数字枚举不成为公共协议。

服务端 `NodeTypeCatalog` 返回 `Designable / Publishable / Executable` 状态。前端只能发布当前部署已经 `Publishable + Executable` 的闭合节点集合；目录应同步提供配置版本、支持的选项和分支等限制，防止客户端与服务端各自硬编码出不同上限。已有节点的新配置也必须经过能力校验；“审批人可执行”不意味着监听器、签名或任何指派方式都已可执行。规划中的空节点具有无副作用的自动继续语义，保留稳定标识和轨迹，不能作为布局占位直接消除。

### 5.2 Workflow-Vue3 资产边界

- 选择性迁移树形插入、分支编辑、节点卡片和已批准 Drawer，不迁移旧项目 C#/SqlSugar 运行时、数字 NodeType、无版本 FlowJson、`Math.random()` Id、Mock API、远程字体/图片或 Debug 覆盖层。
- 任意 `new Function`、脚本投票、未受控远程参数透传和直写其他模块表均禁止。投票和条件使用有界声明式规则；触发器使用受控连接器及强类型输入输出映射。不得通过简单移除现有适配器危险字段过滤来开放新增节点。
- 实现前归档作者授权、上游提交、本地修改范围、再分发条件和第三方声明；不得把第三方来源标记为 Full.NET 自有 MIT 源码。

VForm3 的 H5 预览是 Web 预览能力，不等同于 uni-app/小程序或 Flutter 已支持。跨端投影缺口不得通过裁剪后台原版组件解决；发布到未支持目标时明确诊断，保留完整设计稿，后二开按实际客户端逐项接入。

## 8. 状态、事务、并发与恢复

- Definition Draft 可变；每次 Publish 创建更高 VersionNumber，不可变版本只能新增不能修补。
- Instance 持久化状态键为 `active / completed / rejected / cancelled / suspended`；原规格 Running 对应 `active`。Reject 保持终态；普通发起人撤回另设前置条件、权限与审计，不复用管理员取消来表达。
- Step 状态为 `Pending / Active / Completed / Rejected / Cancelled / TimedOut / Returned / RolledBack`；Todo 只能由 Active 走向已办理或关闭。
- 多人审批节点激活时只创建一个 Step，冻结至多20名去重可信成员及来源依据；纯显式模式至少2人，动态来源可解析为1人。`all` 的法定票数为 M，`any` 为1，`nOfM` 必须满足 `1 < N < M`；`percent` 固化实际分母并向上取整。赞成票达到门槛时批准，赞成票加剩余票不足门槛时驳回，收敛后其余未决 Slot/Todo 统一取消。
- `sequential` 保留同一步骤全部固定有序席位，必须全部同意；首次只建立首人的真实 Todo，后续未激活席位没有 Todo、输入视图、到达时间或提醒。每次同意后同事务以席位修订CAS绑定下一人新 Todo，捕获轮到该人时实际主/分支输入；驳回或取消同时关闭未激活席位。并发同键请求只返回首次结果，不重复创建后继。297成对迁移及双库并发证据见实施记录；分组与投票仍须分别定义收敛规则。
- Slot 投票、Step/Instance 推进、动作回执和审计使用同一实例行锁顺序与本地事务；相同办理人、动作、请求摘要和幂等键必须返回首次持久化结果，不能用随后变化的票数重算回放响应。
- `selected_completed_human_step` 退回策略只接受同实例、`Completed` 且类型为 `human.approval` 的当前有效链步骤。来源步骤记为 `Returned`，目标及其之后的旧完成链记为 `RolledBack` 并永久退出合法候选；目标节点创建新的 Step/Todo 尝试，保留旧记录作为历史，不重新执行中间自动节点。
- Step 以实例内严格单调 `ExecutionSequence` 表达执行位置，候选按该序号倒序分页，退回失效不得依赖可回拨或被数据库截断的时间戳。按开发底座直接演进规则调整目标结构并同步全部写入方，不保留仅为旧版本滚动写入设置的可空列或兼容分支；若实际保留数据需补序号，只能依据可证明的执行事实重建，无法确定的实例阻止退回并进入显式修复，不能猜测顺序或静默丢数据。序号不替代并行分支的因果关系，见 §8.2。
- Start、Todo 动作和恢复命令均要求 IdempotencyKey；写操作携带 ExpectedRevision，重复相同请求返回同一确定结果，冲突返回稳定 ProblemDetails。
- 表单 Patch、Todo 动作、步骤/实例推进、execution log、模块自有 `fn_workflow_domain_audit` 和必要 Outbox 在同一 Workflow 本地事务提交。事务内禁止调用其他模块或外部 Provider。
- Worker/API 使用 `LeaseOwner + LeaseUntilUtc + LeaseGeneration`；过期可重领，续租、终态和恢复使用一致锁顺序。失败达到上限进入 Suspended，强制恢复需要独立权限和审计。

### 8.1 完整节点所需执行基础（In progress）

执行基础必须在 WF-R1 完成，先于空节点、新人工节点和外部活动。现有 `WorkflowInstanceManagementService` 启动路径要求首次人工待办，且在激活后才写 FormSubmission；仅删除编译器“必须人审”检查不足以支持自动流程。

1. **启动与推进。** 统一表达自动继续、等待、定时唤醒、分叉/汇合与失败恢复，处理器静态注册。先在同一 Workflow 事务建立实例、已校验初始表单及必要的本地执行事实，再推进纯本地节点或持久入队；Files 授权准备走受控 Port，不把其写操作并入 Workflow 事务。首次执行可以立即完成、等待活动或产生零至多个 Todo。启动回执、日志、查询、客户端及真实启动消费者都不得假设必有 FirstTodoId；现有可空 ActiveTodoId 需正确表达无人工任务。重放返回原启动回执。审批类流程保留不可绕过的人审策略，自动流程按自身规则校验，流程类别及调用方资格均由服务端约束。
2. **有界推进。** 限制单次事务/调度推进步数、总激活数、分支数和执行时长，达到调度步数上限则持久化继续工作项；总预算耗尽挂起并记录原因，不能用大循环占满请求线程。工作项与状态迁移同事务；禁止以进程内计时器或无人观察的后台任务保存业务事实。
3. **外部调用。** 同步触发器阻断后继直至结果持久化，但不持有跨外部调用的数据库事务。跨模块写入通过事务 Outbox、幂等消费者和结果回传；同模块工作项可本地持久化。HTTP 连接器固定配置版本、出站目标、凭据引用、超时、大小限制和映射；出站解析与每次重定向均校验允许的目的地址，禁止未授权内网/元数据访问及凭据转发。
4. **异步与终态。** 异步触发器在耐久入队后继续后继，完成消息只写活动结果；需要该结果的路径须声明等待依赖并经编译校验无依赖环，不能读未就绪字段。编译器在消费者之前建立内部等待点，不增加参考菜单外的必选节点；有回填但无下游消费者时在结束前建立等待点。结果在等待点才按受控映射并入表单。流程成功终态必须等待所有必需异步活动收敛；不能“只投递就标完成”，也不能在终态后改表单或再次发布业务终态。通知抄送等非阻断知会保留原有独立投递语义，不混作必需业务活动。
5. **重试与不确定结果。** 重试共用稳定业务幂等键；租约世代只防止旧 Worker 提交，不能保证远端只执行一次。远端需支持幂等请求或按业务键查询结果；超时但可能已生效、且无法安全确认的调用进入活动 `outcome_unknown` 并挂起实例等待对账，禁止盲重试有副作用的请求。确定性业务拒绝、权限失败不自动重试；可重试故障有退避和上限，恢复/对账须审计。
6. **暂停、取消与晚到结果。** 暂停禁止新活动分发和后继推进，已在途结果可以持久接收，恢复后才推进。取消/终态竞争按实例修订、激活身份和租约世代原子裁决；迟到结果仅记入原活动的对账事实，不能复活待办。取消不能撤销已经发生的远端副作用，未确认结果继续进入对账，补偿必须由业务所有者执行且有独立幂等键。根实例业务键释放不表示外部副作用已回滚。
7. **计时。** 激活时将绝对时间或相对时长解析为 DueAtUtc 并保存原时区、输入和日历版本；无明确偏移的歧义时间拒绝。纯时长按墙钟计算，工作时长必须显式绑定日历。暂停冻结相对等待的剩余时长，绝对时间不平移；恢复时已到期的绝对等待只唤醒一次。业务截止/SLA 是否扣除暂停时间是独立已发布策略，不从计时器行为推断；取消后定时唤醒失效。
8. **字段并发。** 人工 Patch 携带 ExpectedFormRevision，自动输出使用其输入快照版本；字段写入同时检查当前激活权限和 Schema。串行路径冲突返回明确错误或挂起待处理，禁止仅刷新 Revision 重放旧 Patch。并行分支及并行子实例在固化输入上产生局部输出，汇合按稳定分支/ItemKey 合并；默认只允许互不重叠字段，重叠写必须发布时声明有界确定性归约规则，否则拒绝发布。原子保存输出、合并回执、表单修订与后继推进，重复结果不得重复累加或覆盖人工修改。

跨租户审批使用显式协作授权引用，服务端解析源/目标作用域、允许流程、人员和字段/文件范围；客户端 TenantId 不能创建可信上下文。创建目标任务前及读取、办理、结果接纳时检查授权仍有效。撤销后禁止新读取/办理/推进，已有请求进入取消与对账；与完成并发时以权威授权修订及已提交事实裁决并审计，不能继续信任旧缓存许可。

## 9. 跨模块协作

1. 启动可由受信任同步 Port 返回 InstanceId，或由有真实消费者的版本化 StartRequested 事件触发；Workflow 为数据所有者。
2. Completed/Rejected/Cancelled 结果只有真实消费方确定后才建立具体 MemoryPack 事件；Workflow 同事务写 Outbox，业务模块用 Inbox 幂等收敛。子实例只回报父活动，根业务结果按 §8.2 单一发布；自动流程的立即完成也必须覆盖现有真实消费者的启动/终态到达顺序。
3. Assigned/Completed/Rejected/Cancelled 提醒由 Notifications 消费版本化事件；通知失败不回滚审批事实，依靠 Outbox、重试和对账修复。
4. 业务模块保存的 InstanceId 只是无外键关联快照；不得用跨模块事务保证同时创建。
5. Jobs 只调用 Timeout/Recover 等公开命令；不得持有 Workflow Repository 或 SQL。

## 14. 后续阶段启动门禁

- 已有 DataApproval 与 EnterpriseRequest 真实消费启动及终态契约；新增业务动作必须明确实际接收模块、幂等、补偿与对账语义。
- VForm3 旧安全子集的兼容、包体和浏览器证据仅适用于原记录；完整源码迁入改变依赖/渲染/预览路径，必须按表单计划重新验证相关路径并建立完整功能包体基线，不沿用 8 KB 精简包预算约束完整产品。来源、许可和作者声明继续保留。
- Workflow-Vue3 已迁入资产保留原授权与来源记录；新增迁入资产需核验授权范围、来源内容及本地修改，不能用旧目录摘要证明新内容。
- 新增节点、配置选项、外部 Connector 和跨租户能力按 §5.3、§5.5、§8、§13 完成实施与聚焦验收后才开放；本次文档修订不提升任何运行能力状态。富文本和敏感字段另按各自数据保护要求设计。
