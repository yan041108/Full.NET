# AI 静态并行编排

状态：2026-10-28 本地限定范围验收通过。静态目录、协调器、目标资源授权、检查点、预算、Prompt 和 Vue 人工审批已接线。范围为 AI-D01，属于 `src/AI` 与 Ai 模块，不涉及 Workflow 业务模块。证据及未验证边界见[接替记录](../../verification/2026-10-27-non-workflow-delivery.md#ai-d01-静态并行编排)。

## 拓扑与权限

保留既有线性重命名定义，新增明确版本的静态评审图：读取本人会话 → 有界并行评审 → 汇总 → 结构化校验 → 原人工审批重命名。首版并行分支只允许单次模型节点，只读工具位于组外顺序执行；不并发复用既有单执行器及数据库作用域。禁止并行写工具、递归派生 Agent、动态图、任意插件或模型生成工具目录。并行组连续排列，最多四分支、同时两分支；同组不得引用其他同组结果，汇合输入保持静态顺序。

每次派发仍重新验证原主体、会话、模型版本与精确权限。分支没有新的授权身份，不能扩大根运行工具集。校验不通过、取消、未知结果和任何未完成分支均不得越过汇合或进入审批写节点。

现有线性样例把登录会话身份直接用于聊天重命名目标，二者并非同一资源。运行创建契约须增加明确 `TargetChatSessionId`，按当前主体核对聊天所有权/读写权限，将目标冻结进请求摘要与运行快照；状态里的登录 SessionId 保持原身份语义。新增静态元数据读取工具只返回该目标的身份/标题/版本，不把全部本人会话交给模型。审批继续使用原重命名协议并校验当前目标版本。

## 持久化与恢复

根 RunId 固定，节点 OperationId 从根身份和节点键稳定派生。每次派发先保存明确意图，再调用外部模型；节点完成凭证和输出、累计用量、步数及检查点同事务保存。允许并行组内完成凭证暂时不连续，游标始终指向最早未完成节点；校验必须识别分支组及原输入前缀，不能把洞解释为未执行。

持久化按单一租约串行提交，网络模型请求允许并发，不能并发复用同一个数据库 Session。已提交分支不重跑；未知派发保持对账，未开始分支仅在原额度仍足够且不存在未确定前置条件时恢复。持久汇合必须核对全部必要凭证，不按完成数量猜测节点身份，不从模型输出补造回执。

## 根预算

既有 `AiRunOutputLimitClient` 明确拒绝并发调用，不能直接用 Task.WhenAll 绕过它。并行批次从根剩余输入/输出额度划分互斥上限，分支额度之和不得超过根剩余额度；分支用独立预算外观，底层客户端生命周期仍归根协调器。分支配额与派发意图一起冻结，父账本仅保留一个预留；未知计量不能退回额度或记零。后续批次按全部已提交凭证的实际用量重新计算，历史前缀/凭证合计不符在创建模型客户端前拒绝。

累积执行步数继续遵守根运行 64 次上限，包括拒绝、审批等待及恢复尝试。每分支与根运行共用取消/超时约束；根失败时先停止其他分支并收集可确定的回执，不能遗留后台任务访问已释放的客户端。

实际接线还须把模型派发前复核改为独立 DI/租户作用域；不能让并发模型请求继承使用根数据库 Session 的 `AiChatInputBudgetScope` 回调。单次及并行模型节点均从当前完整凭证合计计算新预算外观，不能继续使用分支执行前构造的陈旧线性余额。检查点准入、Queued 扫描、Prompt 绑定、运行创建/重放、Vue 目标选择及原生闭合状态必须在同批接齐后才能启用新定义。

## 验证边界

集中验证静态拓扑拒绝、真实并发上限、汇合顺序、取消与审批阻断、已完成分支不重跑、未知派发、用量缺失/溢出及根额度不放大；双库覆盖原子分支检查点、租约 fencing、提交故障和部分完成恢复。Native 影响集验证新增闭合状态、源生成和执行路径，不以 JIT 单元替代原生运行；云模型质量与容量不在本批结论中。
