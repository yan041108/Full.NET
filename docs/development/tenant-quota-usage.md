# 租户配额用量概览

Host 租户管理行操作提供“配额用量”，仅需已有 `tenancy.tenant_quota.read` 精确权限；不要求或授予配额管理权限。支持读取非活动企业，页面仅展示账面数据，不调整额度、修复记录或发起预留。

`GET /api/v1/tenancy/tenants/{tenantId}/quota/usage` 返回企业身份、活动状态、读取完成时间和最多两个正式非周期指标：`identity.seats`、`files.storage_bytes`，周期固定 `default`。现有企业没有配置指标时返回空列表，不存在的企业返回 404；匿名或缺权限请求拒绝，租户上下文不能使用 Host 查询。响应使用 `Cache-Control: no-store`。

上限、已用、预留采用 Int64 十进制字符串，生成客户端保持字符串，页面使用 BigInt 计算与格式化，支持 `9223372036854775807`。账面余额为上限减去已用和预留，可能为负；未配置显示“未配置”，不会补零或视为无限额度。上限和计量不代表当前业务一定可用，新增操作仍由租户、订阅及对应业务的权威准入校验决定。

页面显式刷新，暂时读取失败时标明并保留上次成功结果与时间；明确的 401/403/404 清除旧数据。账号、会话、租户、权限或目标变化使在途请求失效，跨目标响应、非正式指标、其他周期、重复项及不规范整数不接入结果。API 使用同模块、一次有界 LEFT JOIN 区分企业不存在与未配置，SQL Server/MySQL 复用同一参数化语句，无结构迁移。

当前验证覆盖正式预留/确认账面链、双库查询、Int64 线格式和页面读取边界；测试中的超大存储计量用于精度验证，不代表实际写入了同等大小文件。成员和真实文件消费者与商业状态的一致性仍按产品化计划的剩余场景验证。
