# 付费订阅账单与履约恢复

Host 租户管理的“订阅管理”复用已发布套餐报价创建账单，并按该账单下单；支付订单页读取或重试原订单履约。分别要求套餐读取、订阅管理、订单创建以及订单读取/对账等现有精确权限，前端显隐不替代服务端授权。

创建前确认报价与明确的 UTC 生效时间。提交后固定套餐、报价版本、生效时间和幂等身份；网络失败或响应不匹配时，不显示成功或新支付链接。关闭后重新打开同一租户的购买弹窗，可点击“恢复原账单”显式重发原请求，服务端复用原身份，页面不会自动重试或生成新身份。

仅当服务端明确返回报价版本冲突，才提供“重新读取并确认报价”：先读取当前报价，人工再次确认后才提交新身份。其他明确拒绝与网络结果未确认使用不同提示；不得通过另建购买绕开未确认结果。

下单未知时“恢复原账单下单”始终使用原订阅身份。成功结果保留在当前弹窗中，不再次显示下单确认。资金状态与权益履约独立展示，已收款不等于权益已发放；履约重试不发起新的支付下单。

履约重试结果未确认时，页面清除旧的重试资格，必须先显式刷新当前订单；只有重新读取后仍为需要人工对账且仍具备精确权限，才允许再次重试。当前目标、会话、租户或权限变化以及组件离开时会取消请求并丢弃迟到响应，取消不保证服务器回滚。关闭同一弹窗仅保留当前组件内的原请求；浏览器刷新或账号上下文变化后应在租户订阅/支付订单列表核对原目标，不据此另建购买。

普通新购恢复沿用原账单条款；同套餐提前续期见下文。所有入口均不引入自动扣款，也不代表外部渠道生产认证已完成。

## 未来生效账单的复核重试

未来账单收款后，履约仍按冻结的生效时间排队。需要人工复核的付款恢复后，也会保持该时间，不会提前调用权益端口或消耗等待期间的失败预算；重试不创建新订单或提前授予权益。生效前退款的复核恢复则立即进入退款处理，不等待原生效日。

此行为复用原账单、资金身份、租约及退款链路，不引入自动扣款、提前续期或新的退款政策。受控渠道的本地双库验证只证明内部状态推进，不能替代商户测试认证。

## 试用与取消操作台

租户管理的订阅入口按 `tenancy.tenant_subscriptions.read` 提供历史读取，包括停用企业；试用与取消另需 `tenancy.tenant_subscriptions.manage`。试用要求企业活动、明确选择当前可用套餐，预览并确认既有三十天起止时间；不再隐式选择第一个套餐。已知有 Trial、Active 或 PastDue 订阅时禁用重复试用，服务端仍负责权威并发判断。

取消前展示原企业、订阅及当前版本并确认；Expired/Cancelled 为只读。取消不会自动发起渠道退款，退款沿支付订单流程处理。提交结果不明或版本冲突后先重读历史，不自动重发；写入成功与随后读取失败分别展示，成功回执不会被读取失败替换。目标变化或撤权会取消当前请求并丢弃迟到结果，取消不保证服务器回滚。该页仅消费既有订阅与支付接口，不改变续期、额度和退款政策。

## 存储消费者履约验证

存储消费者的付款/退款双库恢复用例使用真实本地小文件核对已确认字节、预留和元数据：履约后实际上传成功，退款后新增上传拒绝且不遗留写入，退款保留原文件内容。渠道仍使用确定性替身，此结果只证明内部履约与消费者一致，不能替代真实渠道认证。

## 到期后重新购买原套餐

有管理、套餐读取权限的 Host 操作人可从已到期历史订阅选择“重新购买原套餐”。入口固定历史订阅与原套餐，显式读取当前发布报价，再确认新的生效时间及金额；创建独立的新订阅、新账单和新周期，原历史周期继续保留。原套餐已停用或不在当前目录时显示原因，可通过通用购买入口选择其他可用套餐。

已有 Trial、Active 或 PastDue 订阅时不提供该恢复入口；最终资格仍由服务器判断。该功能消费既有新购与支付链路，不延长旧订阅、不提前叠加仍有效的周期，也不改变已冻结账单、存量权益或退款政策。网络结果不明沿原请求恢复，切换历史来源会取消并丢弃迟到结果；同一来源的列表重读保留账单结果。

## 报价编辑与版本冲突恢复

报价编辑要求套餐读取/更新、功能目录读取和权益绑定四项精确权限。报价和功能目录均读取成功后才允许编辑，只有正式的“报价不存在”404 才按首次创建处理；读取失败不能作为空报价覆盖。保存固定本次草稿、套餐与版本，正文仅包含既有报价契约字段，调整只作用于后续新账单，已冻结账单继续按原条款履约。

报价发布请求和响应的 `amountMinor`、`seatLimit`、`storageLimit` 使用规范十进制 Int64 字符串，创建账单 HTTP 回执的 `amountMinor` 也使用字符串。金额为正，限额非负；不接受 JSON 数字、指数、前导零或 Int64 越界。Vue 输入、草稿比较及用量影响不经过 Number，可完整配置并核对 `9223372036854775807`。有效天数、报价版本仍为有界整数，进程内支付 Port 保留 .NET long。传输精度通过不表示外部支付渠道支持任意金额，仍由现有渠道及商户准入独立判定。

发生版本冲突或保存结果未确认时保留草稿，禁止自动重发 PUT。同一组件关闭重开仍显示原草稿，点击“核对当前报价”只读取当前目标。页面逐项比较收款租户、商户、金额、币种、席位、存储、有效天数、功能和启用状态；当前内容一致不等于已证明本次请求完成，因此不会仅凭内容一致显示保存成功。

核对后可采用当前报价替换草稿，或保留草稿、采用当前版本并再次人工确认保存。后者可能覆盖其他操作人的更新，必须逐项比较；两个选择都不会自动保存。当前报价无法读取时不能采用零版本或继续写入。目标、账号/会话/租户/权限变化或离开组件会取消请求并丢弃迟到结果，取消不保证服务端回滚；浏览器刷新或组件销毁后的本地草稿恢复不在此功能范围内，应重新读取权威报价。

## 支付订单金额与退款入口

支付订单创建和指定金额退款只接受正数金额，最多两位小数；非法后缀、指数、超两位小数及超出 Int64 范围的输入不会发出请求。按整数分解析与展示，不自动四舍五入。退款金额留空仍沿原接口表示全额，实际退款资格和剩余金额由后端判断；缺少退款原因仍拒绝提交。

订单行退款按钮使用后端已有的 `payments.refunds.create` 权限，订单与退款记录工具栏刷新会重新读取。订单和退款金额全程保留规范字符串，列表、详情和冻结回执不经过 Number；错误线格式拒绝接入，不能据此推算退款金额。渠道使用并列选项，指定商户后禁用渠道选择，原下单身份和商户解析规则保持现状。

订单/退款创建请求、列表、详情及订阅下单嵌套订单的 `amountMinor` 统一采用规范十进制 Int64 字符串，例如 29 分为 `"29"`。拒绝 JSON 数字、指数、前导零和越界值；退款金额为 `null` 或省略仍表示全额。元输入按整数解析最多两位小数，最大可表达为 `92233720368547758.07`；这只是传输精度，不代表外部渠道或商户额度认证。输入不使用长度截断冒充合法金额，超过解析预算或存在额外小数均完整拒绝。

支付 HTTP DTO 现由 Payments 主模块 `Contracts/Http` 拥有，轻量 Payments.Contracts 不依赖 Hosting。内部 C# long、数据库、资金事件与渠道适配数值保持不变；使用 HTTP DTO 的 .NET 调用方应引用主模块，公共命名保持现状，旧数字金额不提供兼容分支。订单创建摘要使用独立的固定 UTF-8 字段布局及数值格式，保留既存 SHA-256 结果；HTTP 字符串化不会使同一原请求变成新身份或参数冲突。

当前退款创建、原意图恢复和退款对账只支持微信 Native 订单。其他订单渠道返回 `payments.refund.channel_unsupported`（422），不会借用微信客户端。当前商户的租户和渠道必须与原订单一致；归属漂移返回 `payments.refund.merchant_mismatch`（409），在写入或渠道调用前拒绝。页面禁用非微信订单的退款按钮，仍允许有读取权限的用户核对原退款记录；支付订单本身的支付宝查询不受该退款准入限制。

订单已进入退款中时，服务端只恢复单一原退款意图。金额（空值按原订单全额解释）、首尾空白规范化后的原因及原订单、租户、商户、币种、交易身份均须一致；不一致或存在多个待恢复意图时返回 `payments.refund.request_conflict`（409），不会领取或调用渠道。应先核对原记录，不能修改参数后把旧意图当作新退款。原参数的显式恢复继续使用原退款 ID 和商户退款单号，原有并发租约保护保留。

退款请求一旦发出，当前页面就锁定原订单、金额、规范化原因和提交时间。处理中重复点击不再发送；网络失败、服务端失败或回执身份/金额错配时保留原请求供核对，不能修改正文后直接再次提交。已核验的接收回执也只表示请求已提交，当前页面关闭重开仍不重复发送；它不代表渠道资金已最终退回。

原请求仅保留在当前页面内存。页面离开、刷新或账号/会话/租户/权限变化会清除并取消本地观察；取消不保证服务端回滚，之后应先核对原记录，不将清空页面视为可以重新退款。无读取权限时不会借退款创建权限访问退款记录。列表与退款异步结果按当前会话代次接入，旧会话迟到响应不会覆盖新页面。

Host 用户具有 `payments.refunds.read` 时，可从订单行或退款弹窗的“核对退款记录”按原订单跳转。退款页按原订单 ID、状态在服务端筛选分页；查询按钮提交筛选，翻页沿已提交条件，显式重置才清除深链接条件。无效 UUID 或多值链接不会自动显示全部退款。

退款 ID 可独立于当前列表精确读取，详情展示原订单、商户退款单号、原因、金额、状态和记录时间。刷新失败清空详情并保留请求 ID，避免把旧状态当作新核对结果；错配响应拒绝展示。权限、会话或租户改变取消在途读取并清空详情。该页只有只读查询，查看原记录不代表已向渠道对账，不会创建退款、重试原退款或更新资金事实。

## 支付订单独立只读核对

订单列表可按租户 UUID、八种交易状态和商户订单号条件查询，复用现有服务端搜索语义，在来源分页前筛选。查询按钮提交条件并回到首页；之后的翻页、刷新及操作后的列表回读沿已提交条件，输入草稿不会隐式改变查询。无效租户、状态或过长搜索条件会清空旧页并拒绝读取，不自动回退全局；显式重置才恢复全部订单。

来源返回的页码、大小、租户或状态与请求不符时拒绝整页，不在浏览器过滤成成功结果。新读取取消旧读取且立即清空旧行；加载期间保留分页总数以避免第二页被临时归零夹回首页，完成后采用来源新结果。小屏操作列随表格横向滚动，桌面继续固定，避免遮住订单数据。

Host 用户具有独立的 `payments.orders.read` 时，可在订单列表输入非零 UUID，读取当前页之外的原订单；也可使用订单行详情入口。读取展示租户、商户、渠道、原交易号、金额、支付交易 ID、版本和时间信息。完整 Int64 金额精确显示，拒绝数字或越界响应；支付引导链接仅作为文本，不自动访问或发起支付。

从退款详情“读取原支付订单”追溯时仍须订单读取权限，退款读取权限不能代替。返回订单必须与原退款的订单 ID、租户、商户、原交易号和币种一致，错配拒绝展示。刷新失败清空旧快照，保留请求 ID；账号、会话、租户、权限或页面变化取消并丢弃迟到响应。读取完成时间是页面完成观察的时间，不代表渠道资金发生时间；只读详情不会执行退款或渠道对账。

## 商户配置运营筛选

Host 商户配置列表复用服务端租户、渠道、启用状态和名称条件。筛选提交后才生效，分页及刷新保留已提交条件，草稿变化不改变当前结果。空租户包含全部租户及 Host；非零 UUID、微信/支付宝渠道、三种启用筛选和最长 128 字符的名称在页面校验。非法筛选不发送请求，也不因刷新退回全部；分页或归属不符的来源拒绝整页。列表展示配置 ID、租户及脱敏标识，小屏可横向滚动查看操作。

读取使用 `payments.merchants.read`，创建和更新/停用分别要求既有精确权限。账号、会话、租户、权限或页面变化取消本地观察，清空旧行、未完成确认及明文编辑草稿；迟到响应不会重开窗口或回写。编辑读取须对应原配置、租户、渠道及不倒退的版本，关闭清除密钥输入。停用先确认原配置 ID 与租户，关闭不写入；页面已观察到原行或版本改变时要求重读。确认后继续由既有服务端状态和并发规则裁决，本批未新增预期版本参数或修改商户业务政策。

## 商户配置独立只读详情

具备 `payments.merchants.read` 的 Host 用户，可从商户行“详情”或输入非零商户配置 UUID 按 ID 独立读取当前页之外的配置。列表筛选、分页与已打开的详情相互独立，不借详情更改其他记录。只读详情展示当前商户标识、渠道、通知/跳转地址、默认与启用状态、密钥存在标志、版本和本地读取时间；不会提供密钥正文或写入入口，地址只作文本展示。

行入口固定原 ID、租户、渠道及不倒退的版本，错配拒绝展示。详情代表当前配置，不是历史资金订单的商户快照，也不代表渠道认证通过。刷新失败清空旧快照并保留原 ID；账号、会话、租户、权限、目标或页面变化取消旧观察，迟到响应不能打开或覆盖详情。读取时间是本地完成观察的时间。创建、更新或停用权限不能代替独立读取权限。

## 支付订单原创建请求恢复

直接创建订单会在首次发送前冻结租户、原创建请求键和规范正文。响应丢失、渠道失败或回执无法核对时，关闭重开仍保留这份请求，输入不可改写；“恢复原创建请求”只重放相同正文和键。仅首次请求明确在意图落库前被校验拒绝时允许修正。恢复期间的同码失败不能证明首次请求未受理，仍保留原身份。

具有独立 `payments.orders.read` 权限的 Host 用户，可按租户及原创建请求键只读核对。接口 `GET /api/v1/payments/orders/creation-requests/{idempotencyKey}?tenantId={tenantId}` 返回本地持久化订单及服务器读取时间，使用 no-store，不调用渠道或写入。创建权限不能替代读取权限；404 不能证明请求从未受理。只读角色也可从订单页独立进入核对窗口，找到后打开原订单详情。

合法回执只说明已定位原订单，页面保留其实际支付状态，不宣称支付成功或已履约。核实后再次打开仍锁定原请求，必须明确选择“创建另一笔独立订单”才生成新键。请求信息仅保存在当前页面内存，离开或刷新前应保存原键用于后续核对；账号、会话、租户、权限或页面变化清空并取消本地观察，取消不承诺服务端回滚。

## 人工对账原订单确认

订单行的“对账同步”先只读原订单，再展示订单 ID、租户、商户、渠道、原交易号、精确金额、状态、版本及本地观察完成时间。只有同时具备 `payments.orders.read` 与 `payments.orders.reconcile` 的 Host 用户才可确认；关闭窗口不会查询渠道。确认后的服务端继续校验当前状态，可能同步支付或履约事实，不创建新支付或退款。

当前商户 ID、租户或渠道与原订单不一致时，服务端在远程调用和写入前返回 `payments.order.merchant_mismatch`（409）。退款中订单继续使用原退款对账准入；已退款及不支持的退款渠道仅允许只读核对。

响应不明或回执身份/版本错配时保留未确认状态。关闭重开不会自动重发，必须先显式重读原订单，再决定是否确认；旧快照不是本次结果的证明。已确认回执也须重读后才可再次操作。重读失败清空旧快照，不能用旧版本确认。账号、会话、租户、权限、目标或页面变化取消本地观察并丢弃迟到结果，取消不意味着服务端回滚；页面观察时间不是渠道资金时间。

## 订阅历史详情

只读用户可在订阅历史的“订阅详情”查看原订阅 ID、状态、周期起止、试用截止、取消时间和套餐 ID。套餐名称来自当前目录，不能视为开通时名称快照；目录不再包含套餐时仍保留历史 ID。详情不提供写入操作。

打开与刷新通过精确 GET 固定原订阅身份，独立于列表页和状态筛选。暂时请求失败时明确标记并保留上次成功结果；401/403/404 清除详情内容并保留原 ID，不替换为相同位置的另一条订阅。读取接口使用 no-store；鉴权拒绝或列表内原记录明确不可读后，须重新读取列表再操作。撤权或目标企业改变会关闭旧详情并取消在途读取，同一企业对象的等价重建不清空详情。各层弹窗保留焦点与下层交互隔离。

## 订阅历史状态筛选

Host 订阅历史可按 Trial、Active、PastDue、Cancelled、Expired 筛选，或查看全部状态。只需原订阅读取权限；筛选同样适用于非活动企业的只读历史，不授予取消或创建权限。状态切换回到第一页，后续分页携带同一状态；空值表示全部，未知状态返回 400。总数与分页在 SQL Server/MySQL 使用同一参数化状态条件，并始终绑定目标企业。

切换状态取消旧请求，前一筛选的晚到响应不能覆盖当前结果，其他状态混入的响应拒绝整页。筛选仅影响当前历史视图，不代表企业全部订阅或新增资格；任何创建、重新购买或取消仍由服务端权威校验。详情继续固定原订阅 ID，当前页或筛选未返回时提示重新定位，不替换为其他记录。

原套餐重新购买时，固定套餐以只读名称及 ID 展示，名称来自当前目录，不能改选其他套餐；报价读取、原历史身份及新账单创建规则保持原职责。

## 履约排期与服务器读取快照

订单履约面板在原有只读权限下展示冻结生效时间、当前恢复尝试次数、最近处理码和服务器读取时间；ReadyPaid/ReadyRefund 还展示下一次最早处理时间。人工复核、已完成及其他非自动队列状态不提供自动排期。时间按 UTC 展示，排期不保证届时完成。

“等待生效日”只根据本次服务器读取时间、冻结生效时间和 ReadyPaid 状态判断，不依赖浏览器时钟。跨过该时间后仍需显式刷新；页面不会自行宣称权益已发放，也不会自动调用履约重试。刷新只读取当前订单，原人工重试仍独立要求对账及订阅管理权限。无法核对的时间或状态组合不接入结果。

## 原订单履约重试确认

人工重试先展示固定的原订单、订阅、受益企业和服务器读取时间，确认前不发送重试；返回状态或关闭不会写入。确认区打开时暂停刷新入口，避免将用户看到的快照替换成另一份结果。确认后仍由服务端按当前资金、阶段与租约核对，不创建新订单或再次扣款。

确认按钮获得键盘焦点，返回状态后焦点回到重试入口。订单、会话或权限变化清除确认，重复点击只提交一次；结果不明后仍须显式刷新原订单，再根据当前 Review 状态重新确认。读取权限不能获得重试确认入口。

## 按订阅 ID 定位

在当前企业的订阅历史中输入原订阅 UUID，按 Enter 或“按 ID 读取”即可独立打开详情。支持去除首尾空格和大小写规范化；非法 UUID 不发送请求，空列表也可读取。目标仍限定当前企业，不改变状态筛选、分页或读取资格，不创建/取消订阅。

查不到列表之外的陌生 ID 只清除该详情，不使已读取列表失效；鉴权失败继续整体清除订阅数据。切换企业、账号或会话会清空查找草稿，不将旧 ID 自动发送给新上下文。

## 同套餐手动续期

当前已履约的付费周期可显式读取“同套餐续期”提案；取消续订但原付费周期仍有效也可使用。读取同时要求订阅读取与套餐读取，创建继续要求订阅管理。Trial、未付款、已退款、已到期记录不能作为提前续期来源。页面只展示候选入口，最终资格由服务端验证。

预览固定原订阅、原版本和下一周期开始时间（原周期结束），采用当前发布的同套餐报价。套餐和开始时间不可编辑；确认后生成独立订阅、账单及资金操作，最多保留一笔未来非终态订阅。服务端在同企业根锁内重验来源、报价及冲突；正常新购和试用也不能绕过仍有效的已付款 Cancelled 周期。

付款不提前覆盖当前权益或配额，生效仍依赖原可靠履约队列。下一周期采用新报价，但已用和预留不会清零；新上限低于存量占用时保留资源，并按既有准入停止新增。旧周期取消/退款不自动取消新周期，两个周期分别处理资金和权益来源。

结果未确认时，原请求的来源 ID、来源版本、固定时间及幂等键一起保留。关闭重开或同来源列表刷新后显式恢复仍发送同一请求；服务端先重放已接受请求，来源后来变更、退款或到期不使它变成另一笔创建。浏览器整页刷新或身份变化后仍须先核对原订阅和订单。不含自动扣款、跨套餐调整或按比例退款。

## 原冻结付费账单回读

历史详情中的“读取原账单”仅按原企业与订阅 ID 显式读取，使用原订阅读取权限。支持取消、到期、退款与停用企业的历史核对；没有账单返回不存在/不可读取，不按当前套餐目录或新报价补造历史。金额、席位和字节上限使用精确十进制字符串，避免浏览器把大整数四舍五入。

原商品名称、报价版本、周期、续期来源/版本、已接收付款订单及服务器读取时间均来自原冻结账单。账单接收阶段反映 Tenancy 已处理的历史事实，不替代当前资金或权益判断。读取不会下单、退款或重试，也不会放宽原付款接口对企业和订阅资格的校验。

刷新临时失败保留原快照及原读取时间；明确 401/403/404、目标或身份变化会清除旧账单并丢弃迟到结果。当前订阅详情与原账单分别读取，核对时请查看各自的快照和时间。

原冻结账单含有效续期来源时，可选择“查看原续期来源”。来源不必出现在当前页或筛选内；页面固定当前企业，用来源 ID 独立读取，不改变历史列表。切换会取消旧详情请求并清除上一张账单，完成后焦点回到原订阅刷新按钮；404 保留请求的来源 ID 供核对。普通购买、空或自指来源不提供追溯入口，来源详情不会自动再读取另一张账单。

## 下周期换套餐

当前已履约周期可选择“下周期换套餐”，显式选择其他活动套餐并读取其报价。原套餐退出销售后仍可迁往活动新套餐；同套餐续期则继续要求原套餐可销售。提案同时返回原套餐标识和目标报价，起点固定为原付费周期结束，创建在原企业根锁内复核来源/版本、目标/报价及未来周期冲突。

新周期使用独立订阅、账单和支付身份，按完整的新报价付款。当前周期保持原期限和价格；新周期真正履约后才绑定目标套餐、授予新来源及切换限额，保留已有用量和预留。取消和退款沿各自原记录处理，没有比例结算或自动抵扣；新低限额由现有准入停止新增，既有资源继续保留。

未知结果固定原目标、原来源和幂等键，目标随后退出销售也允许按原身份核对。只有服务端明确拒绝停用目标且确认未创建账单，才提供重新选择活动目标；版本冲突沿显式重新读取/确认提案，新提案不自动创建。页面关闭重开仍恢复当前组件内的原请求；整页刷新或身份变更后先从原订阅/账单和订单核对，不据此另建。
