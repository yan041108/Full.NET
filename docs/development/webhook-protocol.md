# Webhook 签名 v1

本规范按现行产品化计划冻结投递时间、密钥与事件身份的签名边界。当前开发底座直接升级发送器、接收样例及 SDK；接收方配置公开 KeyId 和对应秘密后再启用订阅。

事件正文保持 PascalCase 与原 UTF-8 字节，业务发生时间 `OccurredAtUtc` 保留原事实。每次实际外发生成新的 Unix 秒投递时间，重试和人工重放保留原 EventId/DeliveryId。

| HTTP 头 | 规范 |
| --- | --- |
| X-FullNet-Signature-Version | 固定 `1` |
| X-FullNet-Key-Id | 当前签名密钥的公开 UUID；标准 D 格式 |
| X-FullNet-Timestamp | 非负 Unix 秒，十进制且无前导零 |
| X-FullNet-Event-Id | 原业务事件 UUID |
| X-FullNet-Delivery-Id | 原投递 UUID |
| X-FullNet-Event-Type | 原事件键，1～128 个可打印 ASCII 字符 |
| X-FullNet-Signature | HMAC-SHA256 的 64 位十六进制摘要 |

对原始请求体字节计算 SHA-256，转为大写十六进制。以下字段依次以单个 LF 连接，末尾不加换行；UUID 统一为小写 D 格式，时间为规范十进制：

```text
fullnet.webhook/1
<timestamp>
<keyId>
<eventId>
<deliveryId>
<eventType>
<payloadSha256UpperHex>
```

将此规范字符串按无 BOM UTF-8 编码，使用原秘密的 UTF-8 字节计算 HMAC-SHA256。发送器输出大写签名，接收方按字节进行恒定时间验证，十六进制大小写均可读取；不能解析正文再序列化后验签，也不能遗漏元数据。

接收方只接受受保护配置中明确允许的 KeyId，并据此解析秘密，不把未认证的 KeyId 当作远程地址。默认过去/未来容差均为 300 秒，可由受信策略设置 1～3600 秒；独立读取秘密和加密验证后再次检查时间，避免等待跨越窗口。签名未知版本、缺少/重复头、无效身份、秘密不可取得、超窗或不匹配均不能确认消费。系统保持可靠时间同步，业务发生时间不用于替代投递时间。

验签通过后仍须核对正文企业、事件键和事件身份；以原事件身份在接收方事务 Inbox 去重并与业务写入同提交。同事件不同正文拒绝，当前时间窗内的重复请求仍可能出现；重试更新投递时间与签名，不能因此变成新业务事件。旧签名不能延长到窗口以外，SDK 和样例不自动遗忘去重回执。

订阅公开 SigningKeyId；初始身份复用应用端生成的订阅 UUID，历史迁移只回填缺失身份，不改秘密或投递事实。轮换使用应用端新 UUID v7，必须先准备并配置接收方，再明确激活，不隐式保留无期限旧密钥。

## 明确轮换

企业操作者须同时具备 `webhooks.subscriptions.read` 和 `webhooks.subscriptions.rotate_signing_key` 及有效当前会话。以 `/api/v1/webhooks/subscriptions/{subscriptionId}/signing-key-rotations` 为根：

| 方法/相对路径 | 输入/结果 |
| --- | --- |
| POST 根路径 | 固定 operationId、原 version、新 signingSecret；返回 prepared 回执及公开新 KeyId，当前活动密钥不变 |
| GET /pending | 原订阅当前准备；没有时 404，不代表一项未知在途写入未提交 |
| GET /{operationId} | 原操作的准备/完成回执；只需读取权限 |
| POST /{operationId}/activate | 当前确认 version 和准备的 signingKeyId；原子切换活动身份及加密秘密 |
| POST /{operationId}/cancel | 同样明确确认 version 和 signingKeyId；清除准备材料，原活动密钥不变 |

每个订阅最多一个准备；准备及完成均推进订阅修订，与暂停/恢复共同使用 CAS。响应不含秘密、加密材料、指纹或操作者会话。原操作重复准备必须属于原准备人并匹配原版本及秘密；指纹使用独立 Data Protection 用途加密，不能保存可离线猜测的明文秘密摘要。准备人离开后，另一持有精确权限的当前操作者可明确完成或取消，审计同时保留准备人与完成人。相同完成操作按原确认修订及完成人返回不可变原回执；不同动作或修订冲突。未知响应沿用原操作与原确认输入，只读取不会激活、取消或自动重发 POST。

准备秘密仅在 prepared 状态加密保存，激活/取消即在同一事务清除；加密输入指纹和审计事实保留。提交前通过独立连接重新核对当前会话与精确权限，任何撤权、过期、容量或审计失败均回滚活动指针及准备状态。此处是本地配置及领域审计，不发送新的业务事件或重置历史投递。

接收方在激活前配置新 KeyId/秘密和明确的旧键退役时间。发送器在每次实际外发前读取一次当前身份/秘密原子快照，整批领取时的旧材料不再作为发送依据；已进入发送边界的旧请求仍可能到达，不能把激活解释为即时撤回公网请求。接收端按自己的受信截止时间停止允许旧键，该截止时间独立于每次请求的签名时间窗；过期后即使旧秘密生成新签名也拒绝。样例最多允许两个 KeyId，仅一个可无截止时间，旧键剩余期限最多一小时。迟到旧请求可能失败，后续重试读取新活动密钥并保留原事件身份；业务去重仍由原回执负责，不承诺自动跳过发送方重试上限。

跨语言固定测试向量与原文位于 `contracts/webhooks/signature-v1.vector.json`。向量秘密为公开测试数据，生产使用独立受保护随机秘密。发送器、接收样例和安装包均核对同一向量。
