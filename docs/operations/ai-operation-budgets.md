# AI 操作预算与费用记账

## 当前入口

`IAiOperationBudgetStore` 由 Ai 模块实现。聊天在启动 SSE 和创建模型客户端前预留，Host 与租户均记账；收尾在独立数据作用域结算。Agent/Embedding 使用相同契约，实际派发消费者分别随后续运行时与 Embedding 任务接入。连通性探测仅 GET models/tags，不调用推理接口。

服务端调用方须先校验模型与会话授权。预算请求没有 TenantId 字段，范围从可信上下文编码为 `host` 或租户 UUID；该 Port 不能代替用户授权。OperationId 是应用生成的 UUID v7。摘要不同的重复操作拒绝；摘要相同时返回原凭据且 `IsNew=false`，调用方不得再次派发。摘要包含完整历史、模型配置版本、端点和组织，账本不保存原始提示、密钥或响应。

## 默认上限与配置

```json
{
  "FullNet": {
    "Ai": {
      "Budgets": {
        "MonthlyRequestLimit": 1000,
        "MonthlyTokenLimit": 10000000,
        "RunRequestLimit": 100,
        "RunTokenLimit": 1000000,
        "Currency": "USD"
      }
    }
  }
}
```

这些是每个 Host/租户范围的月度上限与每个 Run 的总上限，来自部署配置，不能通过模型参数调整。Run 跨月也不重置总额度；每个已接受操作始终占一次请求。现有租户显式配额在同一本地事务作为额外限制执行；关闭旧配额不关闭新的服务端默认上限。配置变更按部署重启生效；已经消耗的预算不会因限额降低而被删除。

预留值是完整历史 UTF-8 大小加结构余量及最大输出的保守估计，并不是经过认证的供应商计量上界。当前 Provider 未完成硬费用认证：请求设置 `RequireHardCostLimit`、配置 `MonthlyCostLimit`，或 Run 配置 `RunCostLimit` 时，返回 `ai.budget.hard_cost_unavailable`，不会调用模型。不要为启用硬预算伪造计量认证。

## 已知官方 Embedding 输入准入

官方 `https://api.openai.com/v1` 目的地的 `text-embedding-3-small` 和 `text-embedding-3-large`，在能力测试、知识查询及文本/PDF/DOCX 索引预算准入前使用仓库固定离线 `cl100k_base` 词表校验。单条采用 8191 Token 保守上限；无效 Unicode 拒绝，词表缺失或摘要漂移失败关闭，不回退为字符估算。依据为 [官方 API 输入限制](https://developers.openai.com/api/reference/resources/embeddings/methods/create)与 [官方长输入 Cookbook](https://github.com/openai/openai-cookbook/blob/main/examples/Embedding_long_inputs.ipynb)。

原有 16 条、单条 8000 字符、整批 32000 字符边界继续适用；结合每条 8191 Token，整批最多 131056 Token，低于官方 300000 Token 请求上限。门禁不裁剪或重写输入，早于客户端创建、收费预留及索引批次身份写入；拒绝不需要结算零用量。

只认可官方目的地的精确原始形式及两个精确模型名。主机/协议大小写、显式443与末尾斜杠沿用已核准等价形式；兼容网关、路径变体及其他模型不据此取得精确 Token 认证，仍遵守原字符、授权、预算和网络规则。私有化模式不会因此获得公网回退。

准入 Token 计数与持久预算协议分开：原 UTF-8 字节加余量预留数值、请求摘要和历史索引回执保持不变，不改写旧账本。该切片不是 Provider 用量或硬费用认证；完整 Chat 输入硬限、其他模型/网关词表证明及未知外部费用对账仍待后续。

## 价格与用量

价格存于 `fn_ai_model_price`，目前通过受控 Host 数据维护流程追加版本，没有开放价格 CRUD API。运维必须提供 UUID v7 版本、模型配置 Id、大小写精确的 ProviderKey/ModelId、三位大写币种、ValidFromUtc 及每百万 Token 费率。费率使用 `decimal(20,8)`；普通输入和输出费率在 0 至 1000000 之间，缓存输入费率不得高于普通输入费率。不要更新已发布价格行来改写历史，价格调整追加新版本。

操作在预留时固化价格版本、费率和币种，结算不查询最新价格。`ReservedCost`/`ChargedCost` 使用 decimal，向上舍入到八位小数；价格未知时为空，绝不自动填零。`UsageStatus=known` 表示输入/输出 Token 已知；缓存计量缺失时按普通输入费率保守计费，`ChargedCost` 不等于已核实的供应商账单。

`reserved → unknown → known`：失败、取消或缺少完整用量时保留预留，可在取得可信完整用量后补录；相同已知回执重试不重复调整，冲突回执拒绝，旧 unknown 回执不会覆盖 known。迟到结算更新原月份账本；旧租户配额只调整仍在原月份的计数，不能扣减新月份。进程退出、回执提交结果未知时，按相同 OperationId 重试记账，不能据此重放模型请求；自动对账调度随持久运行任务建设。

## 工作流与工具循环的累计计量

工作流模型节点和工具循环的输入、输出 Token 分别累计。首次调用前的空值表示尚未计量，第一份已知计量可以初始化合计；已有调用后，只要任意一次对应计量未知，该类合计保持 `null`，后续已知值不能把缺失部分当作零补齐。明确报告的零值仍为已知值；恢复到已有模型节点之后的检查点，同样保留未知合计。输入未知不使已知输出合计丢失，反之亦然；结算仍须两类计量完整才标记已知。

供应商负计量或累计超过 `long` 上限时失败关闭，不回绕、不饱和或继续派发工具。工作流先校验输入、输出两类累计量，再一起更新状态，避免只写入其中一类；检查点含负计量时在派发前拒绝。计量异常沿现有协调器失败路径保留未知结算与预留，不据此推断外部模型没有发生费用。

模型与工具等待返回后复核取消，工具在 OperationId 解析后、实际执行器调用前也复核取消。忽略令牌的提供者不能让取消后的响应继续推进节点或返回完成；同一模型响应中的多个工具之间也检查取消。取消并不能证明已派发的外部动作未完成，必须按原 OperationId 与受控回执核对，不能据此免费重发模型请求。本批不提供节点级持久完成证明、崩溃后的模型重放安全或历史计量明细补全，这些仍按 R10 后续恢复与对账建设。

## 工具暂停与模型请求上限

工具执行器返回 `ai.tool.approval_required` 或 `ai.tool.reconciliation_required` 时，工具循环立即暂停，不解析同轮剩余工具的 OperationId、不执行后续工具或继续调用模型。返回空最终文本、已发生的累计用量、工具步数及暂停标志；会话仍是消息摘要，不保存完整工具载荷，也不能据此安全重放外部动作。协调器沿既有审批／对账状态路径处理暂停。

单次文本、工作流和工具循环均通过同一运行级模型请求外观，派发前从剩余额度预留本次上限，每次最大输出为调用方上限、剩余额度与 4096 的最小值。只有合法完整的已知输出回执才退回未用额度；未知用量保留全部预留，实际计量仍为 `null`，不能当作零费用。异常、取消或超额／负计量关闭后续模型派发，拒绝并发请求；外观克隆选项，底层客户端仍由协调器释放一次。

流只允许枚举一次，全程检查请求和枚举取消令牌，读取、计量或释放失败关闭剩余额度；正常结束及提前释放仍保留本次上限，不以部分流退回预留。取消属于协作检查，不能强制中断已进入提供者的请求或证明未发生费用。

三类运行同时按供应商输入回执扣减冻结输入额度；已知零值不消耗额度，输入回执缺失则关闭后续模型派发，实际用量仍为 `null`。超出剩余输入或负计量拒绝交付该响应，禁止由它继续派发工具。输入没有供应商认证的请求前分词上界，允许派发时仍可能由本次外部请求超出额度，此校验不能撤销已发生调用或费用。流派发保守占用全部剩余输入，合法、零值或部分回执均不退回；逐条累计输入回执超过本次剩余量时同样拒绝交付。

工作流恢复在创建客户端前扣减已确认累计输入与输出；有剩余模型时，任一类别未知、耗尽及超限均拒绝继续派发。新节点凭证分别核对输入／输出合计、未知传播与求和溢出；旧前缀只核对新凭证下限，不补造历史计量。无剩余模型时可继续保存未知事实。派发前额度拒绝按 `ai.budget.limit_exceeded` 失败并清除未派发意图，派发后的不可信回执保留对账边界。输出请求上限仍依赖供应商契约，输入实际硬上界未获认证。

工具循环保留最多 8 轮，并将每次模型调用和每个工具请求计入同一 64 步额度；未注册、停用和未获允许的工具也计数。每次派发前检查，超限时不调用后续模型、执行器或 OperationId 解析器；在第 64 步明确要求审批／对账时正常暂停。工具步数字段包含已处理的本地拒绝项。当前上限覆盖单次循环执行，未提供跨审批恢复／崩溃的持久步数计数，不能由此宣称全运行累计硬预算已关闭。升级或回退前须停准入、排空旧 Worker，防止混跑版本绕过新限制。

## 工具派发复核与未知写结果

工具目录在每次读取时重建当前批准策略，不复用请求作用域内的旧远端快照。审计意图保存后，执行器再次检查工具存在、启用、版本、权限、副作用和参数；只在原策略仍匹配、当前主体与会话仍一致时使用当前 Handler。目录、授权、审批及审计等待后都检查取消，忽略令牌的依赖不能继续派发。此检查不是跨外部系统的原子授权，业务 Handler 仍须复核审批消费及业务状态。

写工具进入 Handler 后，异常、取消或超出输出上限都不能证明业务动作未发生，统一返回 `failed`／`ai.tool.reconciliation_required`，不交付输出。回执使用独立取消预算，能保存时记录同一对账错误码；写入失败仍返回对账要求。回执期间取消只阻止输出交付，不改写已保存的成功事实。运行仍有效时，已有工具循环与工作流据此暂停；运行取消或失租时仍沿协调器现有边界收尾，保留审计意图及可保存的回执，不能推断动作未执行。只读工具保持原失败、取消与输出限制语义。原 OperationId 在同一执行器内拒绝重放，跨实例仍依赖既有持久审计主键。该边界只识别未知结果，不提供自动对账、完整输出凭证或崩溃后恢复完成证明。

## 长调用续租与运行期限

Worker 对三种运行分支共用租约监视器，按配置租期的三分之一，在独立数据库作用域续租。每次续租仍使用 RunId、WorkerId、Epoch 和 Version 做 CAS；成功后交接递增版本，Epoch 保持领取时的值。提交前停止后续调度并等待在途续租，避免以旧版本提交；停止调度不能把续租自身的取消异常当作正常收尾。

调用方取消、当前租约到期和冻结的绝对 `DeadlineAtUtc` 共同约束执行令牌。续租拒绝或异常取消执行；数据库续租忽略令牌时，独立期限定时器仍取消模型／工具路径。提交还复核权威 UTC 时钟，SQL 同时检查租约未过期、deadline 未过期和允许的非终态，不能仅凭旧版本在静默到期后写入，终态也不能被改写。

这是协作取消：忽略令牌的模型／数据库调用可能延迟收尾，必须等待其返回并释放资源；其晚到成功或异常不能提交结果或结算预算。已派发外部调用仍可能完成或收费，取消不等于强制中断，也不证明没有外部副作用。静态会话重命名工作流的节点凭证与恢复见下节；其他运行类型的节点凭证、自动外部对账、审批当前再授权及全节点累计预算仍待后续建设。

## 工作流检查点恢复准入

Worker 在建立模型客户端前复核静态定义及检查点归属、定义/格式/框架版本、可推进序号、载荷摘要、JSON、会话、游标与非负用量。游标前的每个已完成节点必须有非空输出；进入重命名或结束位置时，原始标题与结构化模型校验仍须通过执行器共用的规则。损坏或不兼容检查点按 `ai.agent_run.checkpoint_incompatible` 失败关闭，不自动填补缺失输出或重发模型请求；未知/旧版定义按 `ai.agent_run.definition_incompatible` 拒绝。

检查点查询返回后先复核取消，再进行成功或失败处理，避免忽略令牌的查询提供者让已取消请求继续建立客户端、写失败状态或结算预算。正常恢复只执行游标后的节点，并沿用已有未知用量。检查点格式版本仍为1，状态追加 Binding、NodeReceipts 和 PendingNode，旧记录以历史前缀兼容，不补造完成凭证；旧记录若缺失已完成节点输出须保持拒绝，通过受控核对处理，不能靠删除检查点恢复派发。

摘要只校验已存载荷的完整性，不能证明外部节点是否完成、权限是否仍有效或历史用量真实；新的静态会话重命名工作流在派发前持久化意图；历史无凭证记录及其他运行类型仍须受控核对。建议校验也不替代当前工具授权、审批消费和业务状态检查。

## 工作流逐节点意图与完成凭证

静态会话重命名工作流在每个节点派发前，把 PendingNode、确定性 OperationId 和实际输入摘要写入检查点，并追加 run.node_started；提交未确认时不派发。完成后在同一 Ai 模块事务内保存节点步骤、输出摘要、节点用量、已完成前缀及 run.node_completed。节点输出仍保存在检查点中，摘要不是外部系统签名；明确拒绝的校验模型结果也先保存实际输出与用量，再停止业务写入。

Binding 冻结 RunId、定义键/版本、包含静态 Prompt 模板的定义摘要、模型配置标识/版本；恢复前校验每个凭证的节点位置、输入/输出摘要、OperationId 与工具版本形态，当前模型不兼容时在客户端创建前拒绝。旧检查点沿用原准入，LegacyPrefixCount 标明没有新凭证的历史前缀，不补造旧节点记录。格式版本保持1，新字段追加到状态末尾；旧格式兼容不等于历史节点已获得可信完成证明。

恢复存在 PendingNode 的运行直接进入 reconciliation_required，不创建模型客户端或再次派发。派发后的模型网络异常及提供者独立超时同样保存对账态并保留预算预留；调用方取消、失租或deadline到期仍遵守原提交门禁，留下可保存的意图供后续核对，不能声明取消了外部收费。所有新节点均已知完成时不重发节点；整个运行仍复核会话、定义和当前模型兼容性。

续租和节点提交共用串行CAS区域；每次确认提交后交接新的 Version，节点之间继续续租。Worker只自动扫描未超运行deadline、租约已过期、且具有新节点事件及检查点的静态工作流和单模型运行；历史无节点记录、工具循环和已过运行deadline的记录不被猜测为可重放。未知结果仅停止并要求对账，未提供自动外部对账或补偿操作。

事件序号读取最新持久事件，与检查点各自推进；工具循环的等待事件没有检查点也不会重复序号。查询之后的写入仍由租约CAS及事务唯一键保护，失租不会追加事件。节点步骤或末段事件插入失败时，运行版本、步骤、检查点与事件一并回滚。

回退前暂停AI派发并排空在途运行，保留新凭证与待对账状态；旧版Worker会忽略新增意图字段，不得混跑或用旧版重放新记录。当前能力仅覆盖该静态工作流，其他运行类型的逐节点凭证、自动对账、完整审批当前再授权与全节点累计硬预算仍开放。

## 运行失败提交与取消边界

会话失效和运行失败均先提交受租约令牌保护的运行状态。只有提交确认成功，协调器才结算取消或失败预算并计入已处理数量；失租提交被拒绝时，不改写由当前执行者负责的账本。未知用量仍为 `null`，失败或取消的未知结算继续保留预留，不把它当作零费用或释放额度的依据。

模型查询及提示词准入结束后、客户端工厂返回后、单次模型执行器返回后均复核取消。工厂忽略令牌返回的客户端仍按原资源作用域释放；已取消请求不派发节点、不提交晚到成功或失败状态、不结算预算。工厂取消后抛出普通异常也沿取消边界退出。

这些检查属于协作取消，不能证明已派发的外部请求没有完成或收费，其他运行类型仍没有逐节点持久回执，自动未知副作用对账也尚未建设。后续恢复仍须核对原 OperationId 与可信完成证明，不能据此重发模型请求。

## 发布与回退

先执行双库 211 迁移，再部署新 API。迁移仅新增 scope 锁表、操作账本和价格表，不回填旧模型调用。当前月份既有租户显式限额仍受旧计数保护；新 Host/默认预算从切换时开始积累，不能宣称包含迁移前历史。

切换期间应暂停 AI 派发并排空旧版本请求，防止旧节点绕过新账本。应用回退时先停用 AI 派发，保留新表、回执与价格快照；旧版本不会执行新默认限制，不应混跑并宣称统一预算仍有效。不得清空账本来恢复额度。

## 失败与会话拒绝原子结算（R10p）

协调器中原本允许结算的失败收尾、单模型/工作流派发前预算拒绝，以及无需保留派发预算的会话失效收尾，共用 `AiAgentRunCompletion.RejectAsync`。该入口只接受 `failed` 与 `authorization_required`，分别固定映射到 `failed` 与 `cancelled` 结算结果；运行状态、检查点、事件、预算及兼容配额在同一 AI 本地事务内提交。未知计量保留预留额度，不按零用量退款。

失租不结算；预算缺失、结算异常、事件写入失败、取消或物理提交故障会回滚本次收尾。协调器不吞掉结算异常后报告已处理，也不再改判或二次结算；调用方取消仍向上传播。拒绝入口使用未知计量，若账本已有已知计量，沿既有单调规则幂等保留原用量、结果与配额，运行拒绝状态仍可提交；不能将这一情况误判为冲突或覆盖为未知。已有派发凭证要求对账或保留预算的路径继续沿原规则处理，不能因拒绝提交失败而重放外部调用。记录仍按租约和 deadline 约束恢复。

本批不处理用户主动取消接口、历史终态未结算记录、工具循环逐步凭证及自动外部对账。预算 Metrics 在外层物理提交前记录尝试的现有限制仍适用；最终账单以持久账本为准。

## 用户取消与流式终态（R10q）

用户取消 queued/running 运行时，状态更新、租约清除、单调序号 `run.cancelled` 事件及预算 unknown 结算使用同一 AI 本地事务。预算或事件持久化失败时回滚，异常向外传播，不再吞掉失败并返回取消成功；重复取消保持 422，非本人或其他租户保持 404。

取消不证明模型尚未派发，因此不推断零用量、不释放未知计量预留；已经 known 的账本和原结果保持不变。取消成功后旧 Worker 无法续租或提交完成状态，但外部已在途请求可能产生实际用量，仍需对账。历史终态未结算记录不在本批自动修复。

AG-UI 将持久取消事件映射为既有取消快照的终止边界；终态运行先读完全部事件分页，快照读取与取消事件之间发生竞争时刷新状态，避免遗漏或重复结束消息。普通持久事件和对账事件使用已登记的具体 JSON 类型，保持已有字段，避免匿名值在源生成序列化中失败。

本批验证结果在活动计划 R10q 汇总；完整 Native publish/运行与独立生成应用继续按 AI 模块集中验收。预算 Metrics 的外层提交前记录限制未改变，账单仍以持久账本为准。

## 预算指标与物理提交（R10r）

预留成功与结算结果指标在账本写入事务内登记临时观测，由同作用域命令事务协调器等到最外层成功提交后发布。嵌套事务返回不会立即计数；外层异常、失败 Result、取消或提交失败丢弃本轮观测，下一事务不会重放旧回调。该机制收敛了 R10p/R10q 记录的提交前成功指标限制，不改变预算账本或兼容配额的原子性。

调用失败、取消和预算拒绝仍作为尝试指标观察，并不表示账本事实已提交。成功结果仅使用既有固定 status 标签；费用仅在完整已知计量且币种与服务端配置一致时观察，不增加用户、租户、模型或 Run 标签。

指标监听器异常不能把已提交业务结果改判为失败，也不会阻断同轮其他观测。指标属于临时观测，进程退出、提交后资源释放失败或监听器异常可能导致丢失，不保证可靠投递或恰好一次；账单和审计事实仍以持久账本为准。提交观测接口只能在命令协调器拥有的活动事务内使用，不用于可靠业务调用、缓存失效或替代 Outbox。

本批真实双库验证均通过：外层回滚没有成功指标且账本不落库，重试提交后才观察预留/结算与费用，幂等结算不重复观察。完整验证范围及全量架构检查的三项既有失败见活动计划 R10r；Native 发布/运行继续集中验收。

### Agent 请求输入规模准入（R10t）

单模型、静态工作流与工具循环在每次模型调用前共用输入准入。单次最多 128 条消息、累计 512 个内容块、64 条工具声明、每次工具调用 128 个参数；所有文本、标识、选项字符串、工具模式名称及原始 JSON 共用 262144 个 UTF-16 字符。JSON 累计最多 4096 个节点、深度 32，原始转义和内部空白同样计数；使用 .NET 10 原始 UTF-8 只读视图先检查字节长度，再有界复制、计数及解析。来源 JsonDocument 在准入期间须保持存活；冻结只使用独立副本。

超限、未知内容/对象、非空扩展属性、原始请求工厂及未开放的复杂选项在底层客户端调用和输出额度预留前拒绝，沿用 ai.budget.limit_exceeded；本地拒绝不消耗本次额度。消息和工具列表只枚举到首个超限，已转发字段来自同一次捕获的值；工具只转为静态声明，执行仍经统一工具执行器。SDK 默认空工具扩展字典允许进入。取消在枚举和复制前后复核；不能强制中断任意同步枚举器。

该边界只证明服务端接纳规模，字符数不等于模型 Token，网络序列化字节数和实际输入收费尚未硬认证；供应商用量仍按既有回执账本处理。无需迁移或 HTTP 字段变更；升级/回退排空旧运行，旧 Worker 不具备该准入。原生产物、独立生成应用与页面按 AI 模块集中验收，保持 Capacity-not-verified。

## 工具循环整轮凭证与恢复（R10u）

只读工具循环先在租约事务中保存整轮 started 凭证，再调用模型或工具；正常结束先保存 completed 凭证及步骤，然后由同作用域事务完成状态和预算结算。凭证绑定原 Run、会话、定义、模型修订、冻结预算、输入与结果摘要，复用单模型的静态 JSON 格式，不增加表或迁移。

过期 running 工具循环只有存在检查点及节点事件才进入双库扫描。恢复 completed 在当前会话、模型及输入校验后直接收敛原结果和用量，不创建客户端、不执行工具；started、损坏凭证、读取失败或重新领取但没有凭证都进入对账，保留预算。旧消息快照不能解释成未派发。会话撤权只阻止交付并记录 authorization_required，不覆盖之前的预算。

## 索引策略快照准入
