# AI 纯文本 Prompt 版本

本阶段支持 `fullnet-single-text-v1` 的不可变纯文本模板。目录创建只生成草稿；只有显式发布或回滚后，新 Run 才能使用当前发布的版本。语言标签限 `zh-CN`、`en-US`，模板最多 8192 字符且恰好包含一个 `{{input}}`；替换后的文本最多 16384 字符。输入里的占位符作为字面文本保留，不再次解释。

## 权限与操作

所有管理操作同时要求 `ai.agent_runs.read`、`ai.prompts.read` 和下表所列操作权限。作用域来自当前可信 Host/租户上下文，载荷不能指定租户。Host 与 Tenant 的目录互不可见。

| HTTP 操作 | 精确权限 | 效果 |
| --- | --- | --- |
| GET `/api/v1/ai/prompts` | `ai.prompts.read` | 分页目录 |
| GET `/{promptId}/versions` | `ai.prompts.read` | 分页不可变版本 |
| POST `/api/v1/ai/prompts` | `ai.prompts.create` | 创建目录及第一个草稿 |
| POST `/{promptId}/versions` | `ai.prompts.append` | 追加草稿，发布指针不变 |
| POST `/{promptId}/publish` | `ai.prompts.publish` | 显式发布未曾发布的草稿 |
| POST `/{promptId}/rollback` | `ai.prompts.rollback` | 选择曾发布版本，也用于停用后的重新启用 |
| POST `/{promptId}/deactivate` | `ai.prompts.deactivate` | 清空指针并增加撤销代次 |

表中缩写路径均位于 `/api/v1/ai/prompts` 下。写操作携带目录预期 `revision`；409 时刷新目录，重新确认目标。创建的 `clientRequestId` 在本人和当前作用域内幂等，只有名称和规范正文完全相同才恢复原目录。发布、回滚和停用支持直接前一修订的相同结果重试；追加没有客户端幂等键，结果未知时必须刷新，不自动重发。

版本保存正文、模型配置修订、提供程序键、模型标识及 SHA256 摘要。模型配置发生任何修订后，旧版本不能继续创建或执行新模型调用；先追加绑定当前模型配置的新草稿，再确认发布。目录和版本不提供删除端点；迁移 257 保留历史数据，旧消费者回退遵守下述门禁。

## Run 绑定及停用

创建 Run 时可追加 `promptVersionId`，要求本人有效会话、`ai.agent_runs.read/create` 和 `ai.prompts.use`。必须选择当前发布版本，并保持纯文本定义、精确模型配置和版本允许的预算预留值。工具循环、Workflow、动态 Schema 与检索策略暂不接入。

Run 持久化原始输入、精确版本 UUID/序号、完整正文摘要及创建时的撤销代次。发布指针切换不会改写已有 Run；Worker 继续使用已绑定的不可变正文。停用则撤销该代次的旧 Run，即使之后重新发布同一个版本，也不会恢复旧运行。Worker 在建立模型客户端前和调用执行器前，分别复核当前会话、使用权限、作用域、撤销代次、完整正文和模型准入；失败时不发起模型调用，记录失败并结算预算。

Token 字段限制预算**预留**，当前 Agent 提供程序链路不实现实际输入分词及输出请求硬限；不能把这些字段当成实际 Token 数上限或费用硬限。仍需按模型回执计量、预算对账及提供程序侧配额控制成本。实际 Token 硬限属于后续治理工作，R09 不因此关闭。

同一客户端键并发创建时，落败请求没有生成 Run，也没有调用模型，其预留按已知零输入/输出结算，释放 Token 和已定价费用；未定价费用保持为空。请求次数仍计入账本和租户兼容配额。用户取消已创建的 Run 时，缺失用量仍按未知计量保守保留预留。

Vue 管理端在现有 Agent 运行页面管理和选择版本。发布、回滚、停用展示具体目录/修订/版本供用户确认；身份或租户改变时取消请求、关闭本组件确认框并清除正文和 Run 状态。版本冲突和未知结果要求显式刷新。列表首屏展示至多 100 项，更多历史可使用分页 API；没有自动批量发布或自动启用。

## 发布与旧消费者回退

旧 API 会忽略 `promptVersionId`，旧 Worker 会忽略绑定并直接执行原始输入，跳过模板、撤销代次和 Prompt 使用权限复核；当前心跳 `RuntimeVersion` 匹配不能证明旧代码具备此能力。本批未提供自动混布能力协商。启用绑定前，先在所有 API 实例关闭 `FullNet:Ai:AgentRuntime:AcceptsNewRuns`，等待已进入创建流程的请求结束，正常停止旧 Worker，再升级全部 Worker 与全部 API 至本批实现，核对运行产物摘要，再开放新 Run 准入。保留旧消费者的混布环境不得启用绑定。

关闭准入不会停止 Worker 消费排队运行。回退到旧消费者前先关闭所有 API 的新 Run 准入，等待已进入创建流程的请求结束，保持新 Worker 执行现有取消、完成与失败流程。确认所有带绑定的 Run 均已终态、Worker 在途调用均已退出，正常停止现有 Worker 后再替换。数据库取消终态不证明外部模型调用已停止，未知调用状态仍须对账。不能通过删除历史表、清空绑定或只停用目录代替此门禁；当前支持新消费者读取旧的无绑定快照，不宣称旧消费者能安全读取新绑定。新旧混布及旧消费者回退尚未实测。
