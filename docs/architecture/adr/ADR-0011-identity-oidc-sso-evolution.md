# ADR-0011：Identity OIDC 认证中心与 SSO 演进边界

- 决策日期：2026-09-13。

## 1. 上下文

Full.NET 已有自有账号、JWT 与权威会话校验，以及接入外部 IdP 的 OIDC 客户端。希望其他系统通过 Full.NET 完成统一登录，需要补充 OIDC 服务端、客户端授权与多应用会话治理，不能只替换 JWT 签发器。

eShop 可参考账号／协议／UI 分工和授权码流程，但其内存客户端、开发密钥、固定 secret、未强制 PKCE 和关闭 Audience 校验等示例设置不进入 Full.NET 生产基线。源码核对及来源保留在研究报告，不在本 ADR 复制。

## 2. 候选与取舍

| 候选 | 收益与成本 | 决定 |
| --- | --- | --- |
| OpenIddict + 现有 Identity | 复用账号与权限，协议组件支持自定义 Store；需要承担 Dapper Store、会话治理和 AOT 集成成本 | 保持现有路线，先修复治理与生产配置缺口，再按实际证据关闭 P0 |
| Duende + 现有 Identity | 成熟协议组件及产品支持；生产、再分发授权和所选版本闭包另需验证 | 保留备选，不随本 ADR 引入依赖 |
| 外部 IdP | 可直接承担统一登录服务；账号权威源、绑定和撤销联动需要调整 | 保留企业接入路线，不替代本次自有认证中心目标 |
| 自行实现 OAuth/OIDC 协议栈 | 可以完全控制实现，但协议正确性与长期维护风险高 | 不采用 |

## 3. 决定

1. **模块与账号边界。** 认证中心先作为现有 Identity 模块能力，经 Composition 显式装配。保留唯一用户权威源，不引入平行用户库、跨模块 SQL、独立生产认证微服务或未经批准的 EF Core。真实拆分继续受 ADR-0002 门禁约束。
2. **交互协议。** 授权码 + PKCE S256 为交互式接入基线；固定注册两个第一方客户端用于 P0/P1。scope、aud、用户权限、会话和租户分别校验，不把 scope 等同于业务权限，不允许 ID Token 作为业务 API 凭据。
3. **会话模型。** 中心登录会话、客户端会话与刷新令牌族分离；现有轮换记录 ID 不直接成为稳定中心会话标识。账号停用、安全戳变化和强制下线后，旧中心会话不得重新发出有效授权；Full.NET 受保护管理 API 继续检查权威状态。
4. **数据与密钥。** 四类协议 Store 通过自有 Dapper 执行与事务边界实现 SQL Server/MySQL 等价语义。状态改变验证原子消费、乐观并发、撤销与清理；迁移只在 Migrator。签名／加密密钥与 Data Protection 区分职责；JWKS 仅暴露公钥，多实例共享必要状态并验证轮换。
5. **协议契约例外。** Discovery、授权、Token、UserInfo、退出及后续实际启用的撤销／Introspection 端点遵循各自 OAuth/OIDC 标准响应与错误，不套用业务 ProblemDetails、Admin.NET 包络或普通 JSON API 的命名转换。只有明确注册的协议边界适用；客户端管理和其他业务 API 继续遵守标准状态码与 ProblemDetails。不得用协议例外掩盖任意异常或绕过授权、限流、秘密保护。
6. **公开身份最小化。** 稳定 `sub`、客户端／受众绑定和必要身份信息按目标用途发送。内部安全戳和超管权限快照不向一般外部应用暴露；OAuth `scope` 与 `fullnet_scope` 保持独立。
7. **客户端与退出。** 服务端换码的两个应用形成 SSO 边界；Vue 使用现有 API 内的 BFF、服务端回调和共享保护票据，具体实施见 §7。中心会话通过顶层跳转复用，不共享跨域万能 Cookie；当前应用退出、全部应用退出与强制下线分别定义。外部生产接入前，通知失败和离线 JWT 必须有实测失效上界。
8. **阶段与启用。** P0 通过双库、旧会话保护与 Linux Native AOT 后进入 P1；P2 完成授权与会话治理后进入 P3。正式入口对生产的启用须在对应发布验收通过后进行，文档批准不自动启用生产能力。

## 4. 不改变的基线

- API、Worker、Migrator 角色分离；Host.Api 保持现有 Native AOT 约束。
- Dapper 与显式 SQL、UUID v7、模块表所有权及 SQL Server/MySQL 正式支持。
- 登录、刷新、Cookie／CSRF、精确权限、最后一名保护和可信租户安全语义继续有效。按 R-20261017-direct-evolution，不为假定历史消费者强制保留双轨认证；实际收敛需同步调用方、测试和文档，不能通过删除权威检查完成。
- Vue 为唯一后台持续交付线，Layui 保持冻结；P0 的第二客户端是验证夹具，不是第二套后台产品。
- 日志、审计、缓存通知不进入 Outbox；需要可靠跨应用通知时仅按批准的业务通知边界使用 Outbox 与幂等消费。
- 本 ADR 不批准动态客户端注册、机器身份、SAML/CAS、设备流、令牌交换或新的租户账号合并规则。

## 5. 后果与替代规则

本决定增加协议存储、密钥和会话关联的维护成本；收益是业务账号与权限继续保留在 Full.NET，同时支持标准客户端接入。组件宣称支持 AOT 不等于完整应用已经通过原生运行验证。

本 ADR 对 Identity 原规格中“未来替换 IAccessTokenIssuer 即可接入”的描述作补充，并对协议端点限定标准响应例外；其余旧会话契约继续有效。总体架构、Identity 规格和相关规则在同一任务同步，研究报告继续作为原始证据，不反向覆盖已接受决策。

2026-10-27 独立 RP 联调明确：Discovery 地址由含路径的 issuer 派生，BFF 与独立客户端采用同一标准地址。自定义当前应用退出必须绑定已验证 Bearer 的用户、client 与应用会话 ID，只撤销这一会话；Cookie 单独请求不足以选择应用会话，不按用户/client 扩大到其他设备，也不撤回永久同意。标准中心浏览器退出和显式全设备撤销继续保持各自边界。真实网络与所开放 profile 的官方模块证据见[研究报告 §16.7](../../verification/2026-09-13-identity-oidc-sso-research-validation.md#167-2026-10-27-独立-rp真实网络与官方套件补验)，不等同正式 OIDF 认证。

P0 如只能通过关闭 AOT、降低撤销约束、引入不受控反射、改用未经批准 ORM 或放宽租户边界完成，停止该技术路径并记录失败；比较备选、修订本 ADR 后再改变长期边界。正常门禁内的实现选择不需要重复确认。

## 6. 验收与证据

验收用例沿用研究报告 V01—V24，任务映射与执行入口由执行计划维护。历史局部验证按原始记录保留；2026-10-26 静态复核不重新执行或提升这些证据，不声明本轮 `Build-verified`、`Verified` 或 `Aot-published`。测试范围与执行位置唯一来源为[开发质量 §11](../../../rules/development-quality.md#11-测试与验证)：本地实际通过可作为证据，默认只验证本次变更和直接必要边界，未获明确全量授权不得扩大。

## 7. 2026-10-26 改造建议与决策边界

完整证据、成熟产品比较及结论限定见[研究报告 §15](../../verification/2026-09-13-identity-oidc-sso-research-validation.md#15-2026-10-26-模块复核与改造建议)。下列方向已获后续执行授权；实现和验收状态仍分别记录，不能因授权而标记修复完成：

1. **保持 OpenIddict 路线。** 当前差距主要在应用集成与运营治理；更换协议组件不能自动解决客户端状态、会话和租户绑定。Keycloak、Duende、Auth0 保留为具有明确交付期限、商业支持或托管需求时的备选，不新增依赖或独立宿主。
2. **统一客户端权威。** 建议数据库拥有客户端策略；Migrator 受控初始化，API 启动不覆盖管理员变更。显式管理 scope、grant、audience、离线续期与信任级别，多实例缓存不得削弱停用。
3. **完善生产与密钥边界。** 建议生产强制 HTTPS 和持久化协议加密材料；签名密钥激活采用持久化版本与节点协调，区分预发布、激活、验签保留和退役。私钥、协议加密密钥和 Data Protection 均按职责保护。
4. **Vue BFF 与标准退出。** 建议服务端保管令牌并完成 RP 验证，浏览器只持有安全会话 Cookie；优先补 RP-Initiated Logout 和 Back-Channel Logout。标准退出扩展不是全部 OIDC Core 必选能力；现有本地撤销不得被误报为外部应用立即下线。
5. **认证体验按消费者推进。** 建议补 consent、MFA 登录和认证强度表达；企业 IdP 路由、Passkey、组织接入按真实需求评审，不扩大为跨租户账号自动合并、SAML/SCIM 或机器身份建设。

上述方向由唯一活动计划的 B1—B3 记录，实施按已冻结范围与停止条件推进。历史 P0—P3 是能力退出门槛，不要求重新从零实现；旧的强制兼容与 CI 前置已由现行仓库规则替代，历史测试记录不改写。

2026-10-27 的实现沿用本决策：OpenIddict 提供 End Session 协议校验与响应，Identity 事务撤销当前中心浏览器会话。用户必须确认并通过防伪校验；不能凭 `id_token_hint` 撤销其他设备，普通浏览器退出也不能复用按用户撤销全部 grant 的路径。

BFF 在现有 Host.Api 内使用 OpenIddict Client 与现有 Dapper Token Store 完成有状态 RP 回调；OAuth 凭据只进入 Data Protection 保护的共享票据，浏览器 Cookie 是随机句柄。租户切换、改密与注销同步采用不返回令牌的浏览器边界；启用 BFF 时关闭旧人类登录/刷新/OAuth 回调入口，并只信任 OIDC issuer。刷新采用数据库 CAS 租约，未知网络结果或中断租约使票据失效，不重放旧 refresh。

中心或全设备撤销在同一事务写入模块退出意图 Outbox；Worker 幂等落地投递队列，在事务外签发并发送标准 `logout_token`，有界重试与人工重放分别审计。应用管理员只能选择部署方允许的 HTTPS 来源。此 Outbox 承载跨应用安全通知，认证审计仍写本地 Identity 审计表。中心交互同时采用明确第三方同意、本人撤回、已登记 TOTP/一次性恢复码、强制改密与规范语言；`acr/amr` 表达本系统验证结果，不宣称通用 AAL 认证。

密钥治理使用数据库不可重绑的 `kid`/RSA 公钥指纹与单向生命周期，API readiness 和签发通知的 Worker 登记短租约。激活要求预发布窗口、最少 API 数及所有存活签发节点的材料/加密/期限/版本一致，事务 CAS 统一活动指针。旧钥保留覆盖当前配置窗口及现存合法令牌/中心会话的最长到期；退役后资源 API 直接核对权威状态，不能仅依赖本地公钥集合或探针缓存。退役不可逆，活动钥不得退役，节点必须经就绪探针再接流量；生命周期不存储私钥。双库迁移 303 承载公开治理事实和租约，操作步骤见开发入门。实现与新鲜验收分别见研究报告 §16.5—§16.6，真实浏览器与 Linux 原生门禁不得由源码存在替代。
