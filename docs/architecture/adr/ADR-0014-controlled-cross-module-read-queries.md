# ADR-0014：后台查询允许受控跨模块只读关联

- 状态：已批准
- 日期：2026-10-27
- 决策者：项目所有者在当前任务中明确授权
- 替代范围：替代 ADR-0002 中全面禁止跨模块读表、要求后台高频查询默认建设本地投影的条款；其他模块、写入、事务、外键及按证据拆分边界继续有效。

## 背景与取舍

Full.NET 当前是统一部署、共享数据库的模块化单体开发底座。运营订单列表按用户名筛选、排序、分页和统计等查询，若强制使用接口组合或事件投影，会引入大量 ID 传递、同步延迟、回填与对账成本。当前没有要求所有业务模块立即独立部署。

保留严格数据隔离有利于未来拆分，但不作为所有后台查询的默认成本。全面开放读表又会让权限、业务规则和表结构依赖散落。因此采用查询侧受控开放、业务能力和写入所有权保持封装的方案。

## 决策

1. 后台列表、搜索、报表及同语义导出允许显式跨模块只读 `SELECT/JOIN`。集中在所属用例的 `Queries/*Sql.cs`，通过 Full.NET 执行器访问，返回用例 DTO；不新建通用仓储、跨模块实体模型或无需求的独立查询平台。
2. 业务操作、权威状态判断及少量对象的信息组合继续走最小 Contract/Port，同进程不序列化。查询 JOIN 不能复制其他模块的资格、授权、扣款或库存规则；先读后写不能冒充原子保证。
3. 数据只能由所属模块写入。禁止跨模块写表、外键、共享本地事务及分布式事务；重要跨模块状态推进继续采用各模块本地事务、Outbox、幂等、补偿与对账。只读查询不参与命令事务，不使用锁定读，不因此新增 Outbox。
4. 查询必须显式执行租户、成员关系、数据范围、软删除及敏感字段约束。Host 后台不等于无范围访问；跨租户查询必须显式授权。跨模块读取不等于 `SqlDataScope.Global`，Global 目录与查询依赖目录各自校验。
5. 使用 [查询依赖目录](../../../contracts/architecture/module-read-queries.json) 精确登记来源模块、文件、静态成员、Statement 名、SQL SHA-256、用途、外部模块/表/列和安全说明。只允许后台列表、搜索、报表用途；同义导出复用其查询。禁止通配、重复、失效或漂移登记，不能用旧债务目录新增查询许可。
6. 必需的数据所有者必须进入来源模块的运行时 `Dependencies`（可通过已验证的传递依赖闭合）；`OptionalContractDependencies` 不足以保证 JOIN 可用。若依赖形成环，调整查询归属，不增加实现项目引用或绕过依赖 DAG。

## 低成本演进准备

- **集中查询实现**：列表和导出复用查询能力，禁止在 Command、领域服务、后台写任务中散落同一 JOIN。
- **DTO 隔离**：外部 API/页面使用业务查询 DTO，不暴露或依赖对方持久化实体；不保证未来远程化后错误与一致性语义完全不变。
- **登记依赖**：SQL 摘要锁定实际语句，表/列清单记录读取依赖（包括筛选、排序和关联列）；表结构变更必须搜索消费者并更新相关查询与聚焦测试。不得把查询登记成需退役的技术债。
- **保持写入边界**：读表许可不授权业务校验、跨模块更新或事务。仅涉及业务调用时继续使用契约。
- **明确时间语义**：区分用户当前信息与下单时姓名、收货地址、成交价等历史快照；快照由业务所有者按需求保存，不随当前信息自动改写。
- **按需拆分**：只拆有证据的模块。拆分到查询依赖边界时，以登记目录列出影响集，替换为聚合接口、本地投影或专门查询库，并处理回填、同步延迟、失败恢复及接口行为；不提前为所有 JOIN 建设消息投影，也不宣称可无成本拆分。

## 门禁与验证

`ModuleTableOwnershipTests` 保留未登记跨模块表访问检查；新查询登记只放行已验证静态 SQL 字面量对应的源位置，不能豁免同文件的其他语句。`ControlledModuleReadQueryTests` 覆盖登记正例、文件/成员/SQL 漂移、漏表漏列、动态 SQL、写入、锁定读、事务和运行时依赖缺失。静态门禁采取受限语法、失败关闭；不能代替 SQL 语义、权限和数据范围审查。

跨模块外键和本地事务门禁保持。每个真实查询落地时，按变更范围验证 SQL Server/MySQL 的过滤、排序、分页、总数、租户隔离及未授权路径；本决策自身不增加生产查询，不触发双库或全量测试。

## 后果

接受查询侧对表结构的显式依赖，换取当前单体下更直接的后台开发。读取不会因事件传播而额外陈旧，但不承诺超出数据库隔离级别的快照一致性，也不凭架构选择声称性能提升。既有契约和投影按业务需要保留，不在本次规则调整中批量重写。
