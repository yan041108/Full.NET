# ADR-0013：知识库首版检索与文件解析边界

- 日期：2026-10-02
- 状态：R03 选型实验完成后作为 R04–R06 的实施决策；正式知识库能力仍 Planned
- 范围：内部制度、操作手册、产品文档的有界首版知识库
- 活动计划：[AI 计划 R03–R06](../../superpowers/plans/2026-09-08-ai-agentic-web-alignment.md#r03检索-provider-与解析器选型证据p1基础设施决策门)
- 实验入口：[run-retrieval-probe.mjs](../../../tests/ai-evaluation/run-retrieval-probe.mjs)；依赖只存在于独立测试项目，不进入解决方案、生产中央依赖或宿主闭包

## 背景与比较

现有 SQL Server 2022/MySQL 8.0 已承担业务权威数据；知识库尚无生产文档、真实 Embedding 检索或规模基线。本次使用 R02 冻结中文合成集的 12 个问题、13 个片段，验证首版实现路径及安全过滤语义，不能据此认证生产语义质量或容量。

| 候选 | 双库、过滤与中文/编号 | 恢复与运维 | 决定 |
| --- | --- | --- | --- |
| 两库各用原生全文索引 | MySQL 的 ngram 与 SQL Server 的语言断词、停用词及安装组件不同；不能直接给出一致排名契约 | 需要各库独立调参与回归 | 不作为首版共同检索算法；未执行全文排名对比，不断言质量差 |
| 两库存派生向量，SQL 先过滤，再在受控代码中精确余弦排序 | 两库参数化范围查询使用相同模型、版本、代次及同一排序；中文/编号无需依赖数据库分词 | 复用现有数据库备份、部署及权限边界；扫描成本随授权候选数和维度增长 | 首版选用；严格有界，规模上限另由 R05/R06 实测 |
| Qdrant 1.19.1，静态 REST `/points/query` 与 payload 索引 | 同一合成向量、精确模式及服务端 scope/source/model/generation 过滤可比较 | 增加网络、Secret、持久卷、监控、备份与升级责任；集合可从权威源重建 | 保留候选，不增加生产服务/SDK/开关 |

第一行是根据官方能力的架构判断，不是本次全文性能实验结论。参考 [MySQL 8.0 ngram](https://dev.mysql.com/doc/refman/8.0/en/fulltext-search-ngram.html)、[SQL Server 断词组件](https://learn.microsoft.com/en-us/sql/relational-databases/search/full-text-word-breaker-and-stemmer-binaries?view=sql-server-ver17)和 [Qdrant 过滤](https://qdrant.tech/documentation/search/filtering/)。没有规模瓶颈证据，不引入另一套长期数据基础设施。

## 检索决策

1. Ai 模块拥有 `fn_ai_*` 元数据、文档版本、片段、任务及派生向量。正式访问经 Full.NET 自有 Dapper/事务边界，实验项目直接使用驱动仅限新建、用后清理的合成容器。SQL Server/MySQL 是可替代 Provider，不双写。
2. 首版查询先按可信租户/Host 范围、知识库与文档授权、有效来源版本、活动代次及模型空间过滤，再读取有界候选。候选进入上下文前批量查询权威状态；引用读取和历史派生答案复用再次授权。索引与缓存不拥有权限。空允许集直接拒答，不执行无范围查询。
3. 向量空间绑定 Provider、模型标识/版本、维度、归一化/距离、分块和索引格式。检查数值有限、维度正确、非零以及模型和代次一致；同维度不能跨模型。精确余弦使用稳定片段 ID 打破平分，不以数据库默认排序决定结果。
4. 实验的候选保护值为 4096，读取上限加一后超限失败；这不是已测的 4096 片段容量。正式上限必须同时约束候选数、向量字节、维度、SQL 参数、并发与总时限，并由 R05/R06 的实际模型和目标规模双库实验定稿。禁止静默截断候选后宣称完整召回；超限要求缩小知识库范围，错误/超时停止生成，不退化成无范围扫描。
5. 索引属于可重建派生数据。原文归 Files，Ai 保存摘要、文件版本及解析/分块版本；重建从有效权威版本开始，不以旧向量为唯一源。新代次完整写入、校验后以版本条件切换；旧任务禁止恢复删除或撤权的文档。权威拒读先于异步删除向量，失败按幂等任务重试与对账。
6. SQL 派生片段与元数据可在 Ai 本地事务维护，模型及 Files 调用均在事务外。Host 上传关联使用 Pending Claim → Ai 提交 → Confirm，并登记 Ai 消费者/Probe；租户使用 `ITenantResourceFileStore` 的可信模块/资源合同。`IHostFileContentReader` 自身的 FileId 参数不是共享授权；调用者先查已授权的 Ai 引用。首期不导入其他模块附件。

## 解析决策

采用 PdfPig **0.1.16** 的 `ContentOrderTextExtractor` 作为 R05 文本 PDF 解析候选；MD/TXT 采用严格 UTF-8 解码、保留标题/表格文本与稳定位置，不新增 Markdown 引擎。PdfPig 为 Apache-2.0，生产接入时随分发保留完整许可及通知，版本升级重新测试；未复制第三方文档/字体资源。依据 [PdfPig 固定版说明](https://github.com/UglyToad/PdfPig/blob/v0.1.16/README.md)及[许可](https://github.com/UglyToad/PdfPig/blob/v0.1.16/LICENSE)。

首期仅支持可提取文本的 PDF、`.md`、`.txt`；DOCX、扫描件 OCR、网址抓取、嵌入脚本执行和外链访问不支持。空白或无文本页明确失败，不能生成空索引；实验用无文本 PDF 验证此拒绝条件，并未验证真实扫描图片的 OCR。文件扩展名、内容签名/类型与权限必须在 R04/R05 正式入口复核，实验直接指定格式不代表公开上传验证。

实验限制输入 5 MiB、128 页、输出 2 Mi 字符；页码从 1 开始。输出字符限制不等于解压内存限制，PdfPig 同步页面解析也不保证响应 CancellationToken。R05 必须在可强制终止的独立解析进程中处理不可信 PDF，限制文件/页面/输出、内存、解压与总时长，禁用解析进程网络且不提供数据库/模型/存储凭据；进程失败不影响 API 或 Worker 的调度主进程。不得用 `Task.Run` 加超时后遗留后台解析冒充硬限制。具体预算由恶意压缩/损坏文件、超时、取消和原生产物实验确认后才能启用 PDF；本次 512 MiB/2 CPU/60 秒是整个实验进程的外部预算，尚未证明正式解析隔离或解压预算。

## 部署、失败与回退

本次不新增生产配置，不连接生产库，不启用知识库路由。R04–R06 正式功能关闭时不解析、不构建索引或派发模型；错误配置拒绝启动或请求。现有普通聊天能力独立验收。

两库使用既有服务端可信连接配置，SQL Server 加密且验证证书。实验中的自签名证书信任、MySQL 无 TLS、管理员账户及无认证 Qdrant 仅存在于唯一命名临时网络；不能复制到生产。真实模型调用仍经已有目的地、凭据引用、预算和数据分类政策；网络可达不代替文档外发许可，私有化失败不自动切到外部模型。

回退为关闭新增入库/检索/问答派发，保留元数据、已提交任务、文件引用与账本，不改写历史迁移、不恢复已撤权限、不对用户返回旧失效上下文。R08 扩展批量清理与恢复。未来考虑 Qdrant 必须补充目标语料/规模、真实模型评估、ANN 与过滤召回、认证/TLS、最小写查权限、数据保留、快照/重建 RTO/RPO、集群故障及停止/切回验证，另行修订 ADR；本次删除集合再重建不是持久卷丢失或生产灾难恢复验收。

## 证据范围与后续门禁

复现命令、锁文件、实际结果和限制维护在 [R03 实验说明](../../../tests/ai-evaluation/RETRIEVAL-PROBE.md)。固定版本验证真实原生驱动/HTTP/解析调用，不代表正式 Host.Api/Worker 闭包已验证。R05/R06 接入生产后必须重跑受影响分析器、双库与原生路径，R06 在 R02 相同冻结语料上补真实 Embedding、答案/引用、拒答和零泄漏评估。

本决策选用有界、易回退的既有数据库路径；不宣称比 Qdrant 更快，也不把 13 个合成片段外推到 1 万同时在途或大型知识库。全链路保持 `Capacity-not-verified`。
