# Full.NET Application Template

This template creates an independently buildable Full.NET application with a versioned framework source bundle under `framework/fullnet/`.

From the Full.NET source checkout, first assemble and install the template package into an empty output directory:

```bash
node scripts/templates/build-app-template.mjs --output artifacts/templates/fullnet-app-package
dotnet new install artifacts/templates/fullnet-app-package
```

## Parameters

| Symbol | Description | Default |
| --- | --- | --- |
| `name` | Application name | `App` |
| `owner-key` | Application owner key for naming profile (`^[a-z][a-z0-9]{1,11}$`, excluding `fn` and `sys`) | `demo` |
| `database` | `sqlserver` or `mysql` | `sqlserver` |
| `preset` | `minimal`, `platform`, `saas`, or `enterprise` runtime module preset | `minimal` |
| `http-port` | Local HTTP port | `5180` |

## Create an app

```bash
dotnet new fullnet-app --name Demo --owner-key demo --database mysql --preset platform --http-port 5180
```

## Layout

- `framework/fullnet/` — managed framework source bundle and `framework-manifest.json`
- `src/FullNetAppNameToken.Host.Api/` — application-owned API host referencing framework modules
- `fullnet-app.json` — frozen application owner key, database provider, and preset
- `src/FullNetAppNameToken.Host.Api/appsettings.json` — runtime configuration including `FullNet:Modules`

After generation, build with `dotnet build src/<name>.Host.Api/<name>.Host.Api.csproj -c Release`. Secrets are not generated by the template; configure connection strings and signing keys in local user secrets or environment-specific settings.

The preset currently controls runtime module registration. The source bundle still carries the full Composition project reference graph; migration, login, and preset-specific reference closure remain separate acceptance gates.
