# Full.NET 多语言治理契约

本目录统一维护 Full.NET 的规范语言、平台映射、回退别名和术语。它是仓库级治理事实来源，不由生产进程在请求期间读取；各服务端与客户端仍使用平台原生资源机制，并由自动测试检查两者是否一致。

## 文件职责

- `locales.json`：声明规范 BCP 47 标签、默认语言、文本方向、回退别名和各平台内部映射。
- `glossary.json`：固定中英文术语显示。`translate: false` 表示必须使用已经审定的 `display` 值，不能由自动翻译或局部资源自由改写。
- `schemas/locale-catalog.schema.json`：约束语言清单的结构和必填字段。

当前生产语言仅为 `zh-CN` 与 `en-US`。uni-app 的 `zh-Hans`、Flutter 的 `zh_CN` 等值只允许存在于平台适配层；公共 API、持久化值和跨服务契约必须继续使用规范标签。

## 变更流程

新增或调整语言时必须同时完成：

1. 更新 `locales.json` 的规范标签、平台映射、回退和方向；
2. 更新术语表及所有处于维护状态的平台原生资源；
3. 验证日期、数字、货币、复数、长文本、布局方向和组件库语言；
4. 运行 `pnpm test:localization` 与 `pnpm test:workspace`。

资源不完整的语言不得加入生产语言选择器。业务逻辑必须依据稳定错误码、权限码、字段名和枚举值，禁止比较翻译文本。
